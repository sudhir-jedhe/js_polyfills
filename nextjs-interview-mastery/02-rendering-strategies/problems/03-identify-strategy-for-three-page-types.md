# Problem 3: Identify the Rendering Strategy for Three Page Types

## Task

For each of the following, write the route implementation using the correct rendering strategy, and justify the choice in a comment block: (1) a blog post page, (2) a live stock ticker page, (3) a marketing landing page.

## Solution

### 1. Blog post — ISR

```tsx
// app/blog/[slug]/page.tsx
//
// Justification: content is identical for every reader and changes
// rarely after publish (occasional typo fixes). ISR gives SSG-level
// speed with a bounded staleness window, without requiring a full
// redeploy for every content edit. SEO and fast first paint matter,
// ruling out CSR.
export const revalidate = 1800 // 30 minutes

export async function generateStaticParams() {
  const slugs = await getAllPostSlugs()
  return slugs.map((slug) => ({ slug }))
}

export default async function BlogPost({ params }: { params: { slug: string } }) {
  const post = await fetch(`https://cms.example.com/posts/${params.slug}`, {
    next: { revalidate: 1800 },
  }).then((r) => r.json())

  return (
    <article>
      <h1>{post.title}</h1>
      <div dangerouslySetInnerHTML={{ __html: post.html }} />
    </article>
  )
}
```

### 2. Live stock ticker — CSR (island inside a static shell)

```tsx
// app/ticker/page.tsx
//
// Justification: price data changes multiple times per second and is
// meaningless if cached — no server rendering strategy can keep pace
// with that freshness requirement. Server-render the static shell
// (page chrome) and let a Client Component own the live subscription.
import { LiveTicker } from './LiveTicker'

export default function TickerPage() {
  return (
    <div>
      <h1>Live Market Ticker</h1>
      <LiveTicker symbol="ACME" />
    </div>
  )
}
```

```tsx
// app/ticker/LiveTicker.tsx
'use client'
import { useEffect, useState } from 'react'

export function LiveTicker({ symbol }: { symbol: string }) {
  const [price, setPrice] = useState<number | null>(null)

  useEffect(() => {
    const ws = new WebSocket(`wss://stream.example.com/${symbol}`)
    ws.onmessage = (e) => setPrice(JSON.parse(e.data).price)
    return () => ws.close()
  }, [symbol])

  return <span>{symbol}: {price !== null ? `$${price.toFixed(2)}` : 'connecting…'}</span>
}
```

### 3. Marketing landing page — SSG

```tsx
// app/(marketing)/page.tsx
//
// Justification: identical content for every visitor, changes only on
// deploys or infrequent copy edits, and first-paint speed / SEO are
// directly tied to conversion rate. No personalization, no live data —
// there's no reason to pay any per-request rendering cost.
export default async function LandingPage() {
  const copy = await fetch('https://cms.example.com/landing').then((r) => r.json())

  return (
    <main>
      <h1>{copy.headline}</h1>
      <p>{copy.subheadline}</p>
      <a href="/signup">{copy.ctaText}</a>
    </main>
  )
}
```

No `revalidate` export is needed here since there's no `cookies()`/`headers()`/`no-store` usage — the route is statically generated by default and only changes on the next deploy, which matches the "changes rarely" profile described.
