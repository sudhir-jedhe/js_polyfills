The effect function runs **after the initial render and after every single re-render** of the component.

```jsx
useEffect(() => {
  // ⚠️ Runs after initial mount AND after EVERY re-render
  console.log('Component rendered');
}); // No dependency array passed

```

---

**Potential Consequences**

* **Infinite Loops (Critical):** If the effect calls a state setter (`setState`), it schedules a re-render. That re-render triggers the effect again, which calls `setState` again, locking the browser into an infinite cycle until React throws `Maximum update depth exceeded`.
* **Performance Degradation:** Heavy operations (API calls, DOM measurements, event recalculations) execute on every single state or prop change, causing CPU spikes, network spam, and UI lag.
* **Duplicate Subscriptions / Listeners:** If you attach event listeners without a cleanup function, a new listener gets added on every render, leading to memory leaks and multiple handler executions per user action.

---

**Dependency Array Behaviors Compared**

| Syntax                                      | Execution Timing                              | Use Case                                                               |
| ------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------- |
| `useEffect(() => {})` *(No array)*          | Runs after **every render**                   | Logging render cycles, syncing with non-reactive third-party DOM nodes |
| `useEffect(() => {}, [])` *(Empty array)*   | Runs **once** after mount                     | Initial API fetching, setup global event listeners, timer init         |
| `useEffect(() => {}, [a, b])` *(With deps)* | Runs on mount and when **`a` or `b` changes** | Fetching data on ID change, updating UI based on specific prop/state   |
