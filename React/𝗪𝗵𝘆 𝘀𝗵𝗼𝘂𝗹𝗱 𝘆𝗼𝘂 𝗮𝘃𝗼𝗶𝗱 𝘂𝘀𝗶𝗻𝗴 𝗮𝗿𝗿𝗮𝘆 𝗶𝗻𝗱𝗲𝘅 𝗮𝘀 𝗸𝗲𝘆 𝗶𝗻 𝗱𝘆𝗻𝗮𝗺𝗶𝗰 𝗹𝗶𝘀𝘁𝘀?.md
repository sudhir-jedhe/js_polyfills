Using array indices as keys in dynamic lists causes **state mismatches and rendering bugs** whenever items are reordered, inserted, or deleted.

Rather than treating items as new components, React uses keys for its reconciliation algorithm to determine identity: when keys change positions relative to their data, React matches the wrong state and DOM nodes to the wrong elements.

**What Actually Breaks**

* **Uncontrolled Internal State:** Form inputs, text selections, or components with local `useState` retain values based on index position. If you delete the first item at index `0`, the new item moving into index `0` inherits the deleted item's uncontrolled state (e.g., entered text or focused input).
* **Broken Animations & Transitions:** Layout shifts and list transition animations rely on stable keys to calculate positional deltas. Indices mask which item actually moved, causing visual jumps or broken animations.
* **Degraded Performance:** Inserting an item at the beginning shifts every subsequent index (`0 -> 1`, `1 -> 2`, etc.). React assumes every single child mutated and forces a full re-render of the entire list instead of inserting a single DOM node.

---

**Example Breakdown**

```jsx
// ❌ Anti-pattern: Index as key
{todos.map((todo, index) => (
  <TodoItem key={index} text={todo.text} />
))}

// ✅ Recommended: Stable, unique ID
{todos.map((todo) => (
  <TodoItem key={todo.id} text={todo.text} />
))}

```

---

**When Using Index Is Acceptable**

You can safely use the array index as a key only if the list meets **all three** conditions:

1. The list is completely static (no adding, removing, or reordering).
2. The list items have no internal state or uncontrolled DOM inputs.
3. The list is never filtered or sorted dynamically.
