State can be shared without prop drilling or React Context by using **component composition**, **external state management stores**, **URL search parameters**, or **native browser event buses**.

**1. Component Composition (Children / Slots Pattern)**

Pass fully formed JSX elements instead of passing data down multiple layers. This keeps state local to a parent without intermediate components needing to know about the props.

```jsx
function Page() {
  const [user, setUser] = useState({ name: "Alex" });
  return (
    <Layout>
      {/* Layout doesn't need to accept user props */}
      <UserProfile user={user} />
    </Layout>
  );
}

function Layout({ children }) {
  return <main className="container">{children}</main>;
}

```

---

**2. External State Stores (Zustand, Jotai, Valtio)**

Micro-state libraries operate outside the React component tree and use `useSyncExternalStore` under the hood to trigger selective re-renders only in components that read the specific state slice.

```javascript
// store.js (Zustand)
import { create } from 'zustand';

export const useUserStore = create((set) => ({
  user: null,
  setUser: (user) => set({ user }),
}));

```

```jsx
// ComponentA.jsx
function LoginButton() {
  const setUser = useUserStore((state) => state.setUser);
  return <button onClick={() => setUser({ name: 'Alex' })}>Log In</button>;
}

// ComponentB.jsx (Can live anywhere in the tree)
function NavProfile() {
  const user = useUserStore((state) => state.user);
  return <span>{user?.name}</span>;
}

```

---

**3. URL Search Parameters (Query Strings)**

For state that determines view configuration (filters, active tabs, pagination, search queries), serialize state directly into the browser URL.

* **Benefits:** Shareable links, browser history support (`back`/`forward`), zero tree-traversal overhead.
* **Implementation:** Use `useSearchParams` from React Router / Next.js, or native `URLSearchParams` with `window.history.pushState`.

---

**4. Custom Event Emitter / Pub-Sub Pattern**

Components publish and subscribe to a decoupled native or third-party event bus.

```javascript
// bus.js
export const emitter = {
  events: {},
  emit(event, data) {
    (this.events[event] || []).forEach((cb) => cb(data));
  },
  subscribe(event, cb) {
    (this.events[event] = this.events[event] || []).push(cb);
    return () => {
      this.events[event] = this.events[event].filter((fn) => fn !== cb);
    };
  }
};

```

```jsx
// Subscriber.jsx
useEffect(() => {
  const unsubscribe = emitter.subscribe('themeChange', (newTheme) => setTheme(newTheme));
  return () => unsubscribe();
}, []);

```

**Pattern Selection Guide**

| Pattern                            | Best Used For                                                           |
| ---------------------------------- | ----------------------------------------------------------------------- |
| **Component Composition**          | UI layout wrappers, modals, shallow hierarchy nesting                   |
| **External Store (Zustand/Jotai)** | Global app state, shopping carts, authenticated sessions                |
| **URL Parameters**                 | Filtering, sorting, pagination, active tabs                             |
| **Event Bus / Pub-Sub**            | Fire-and-forget cross-component triggers (toasts, analytics, shortcuts) |

A custom hook alone does **not** share state between multiple components.

When you call a custom hook containing `useState` or `useReducer` in two separate components, React creates an **isolated, independent instance of state** for each component call. Updating the state in Component A will have zero effect on Component B.

```jsx
// ❌ Misconception: This does NOT share state between components
function useCounter() {
  const [count, setCount] = useState(0); // Each caller gets its own count
  return { count, setCount };
}

function ComponentA() {
  const { count, setCount } = useCounter(); // Instance 1
  return <button onClick={() => setCount(count + 1)}>A: {count}</button>;
}

function ComponentB() {
  const { count } = useCounter(); // Instance 2 (remains 0 when A updates)
  return <div>B: {count}</div>;
}

```

**How to Make a Custom Hook Actually Share State (Without Context)**

To share state across different invocations of a custom hook without Context or prop drilling, the state must live **outside the React component lifecycle** (module-level scope) and synchronize using React's `useSyncExternalStore`:

```javascript
// store.js - Module-level singleton
let state = { count: 0 };
const listeners = new Set();

export const countStore = {
  getSnapshot: () => state,
  setCount: (fn) => {
    state = { ...state, count: fn(state.count) };
    listeners.forEach((listener) => listener());
  },
  subscribe: (listener) => {
    listeners.add(listener);
    return () => listeners.delete(listener);
  },
};

```

```jsx
// useSharedCounter.js
import { useSyncExternalStore } from 'react';
import { countStore } from './store';

export function useSharedCounter() {
  const state = useSyncExternalStore(countStore.subscribe, countStore.getSnapshot);
  return { count: state.count, setCount: countStore.setCount };
}

```

---

**Valid Alternatives Without Prop Drilling or Context**

* **External State Libraries:** Libraries like **Zustand** or **Jotai** implement custom hooks powered by external singletons under the hood.
* **Component Composition (Slots):** Pass pre-rendered child JSX elements via props (`children`) directly to the top-level parent holding the state.
* **URL Search Params:** Read and write shared filter/view state into the query string (`?filter=active`).

---

**Verdict**

Standard custom hooks share **stateful logic**, not **state values**. To share the actual values across components without Context, the hook must hook into an external singleton store or event bus.
