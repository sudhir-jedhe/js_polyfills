***  23. Suspense 3.md ***

```js
// This is a React Quiz from BFE.dev 

import * as React from 'react'
import { Suspense, useMemo } from 'react'
import { createRoot } from 'react-dom'

const resource = (() => {
  let data = null
  let status = 'pending'
  let fetcher = null
  return {
    get() {
      if (status === 'ready') {
        return data
      }
      if (status === 'pending') {
        fetcher = new Promise((resolve, reject) => {
          setTimeout(() => {
            data = 1
            status = 'ready'
            resolve()
          }, 100)
        })
        status = 'fetching'
      }

      throw fetcher
    }
  }
})()


function A() {
  console.log(1)
  const memoed = useMemo(() => {
    console.log(2)
    return 'memo'
  }, [])

  const data = resource.get()
  console.log(3)
  return memoed + data
}

function App() {
  return <Suspense fallback={null}>
    <A/>
  </Suspense>
}

const root = createRoot(document.getElementById('root'));
root.render(<App/>)

```

### Step-by-Step Breakdown

**1. Initial Render (Suspension)**

* Component **`A`** begins rendering and executes `console.log(1)`, logging **`1`**.
* The `useMemo` hook runs for the first time during component mount (`mountMemo`), executing its factory function and logging **`2`**.
* `resource.get()` is invoked with `status = 'pending'`, which sets up the timer and **throws the pending Promise**.
* Execution of `A` halts before reaching `console.log(3)`. The `<Suspense>` boundary catches the thrown Promise and renders its fallback (`null`).

**2. State During Suspense**

* Because component `A` suspended on mount and never reached the commit phase, no committed fiber exists (`current === null`). The uncommitted work-in-progress hook state is discarded.

**3. Promise Resolution & Retry**

* After ~100ms, the promise resolves and `status` becomes `'ready'`.
* React retries rendering the suspended component **`A`** from scratch as a mount:
* `console.log(1)` executes and logs **`1`**.
* Because this is a fresh mount attempt, `useMemo` runs `mountMemo` again, re-executing the factory function and logging **`2`**.
* `resource.get()` is called again and returns the resolved data (`1`) without throwing.
* `console.log(3)` executes and logs **`3`**.
