### Step-by-Step Breakdown

**1. Initial Render (Suspension)**

* **`App`** renders first and logs **`"App"`**.
* React enters **`<Suspense>`** and begins rendering its child **`A`**.
* **`A`** starts executing and logs **`"A1"`**.
* `resource.get()` is called. Since `status` is `'pending'`, it creates a Promise, updates `status = 'fetching'`, and **throws the Promise**.
* Because the Promise is thrown, execution in `A` halts before reaching `"A2"`.
* The nearest `<Suspense>` boundary catches the thrown Promise, switches to the fallback branch, and renders **`Fallback`**, logging **`"fallback"`**.

**2. Promise Resolution & Re-render**

* After ~100ms, the `setTimeout` finishes: `data` is set to `1`, `status` is set to `'ready'`, and the Promise resolves.
* The resolved Promise notifies React that the suspended subtree is ready to retry rendering.
* React re-renders **`A`**:
* It logs **`"A1"`**.
* `resource.get()` is called again. Because `status === 'ready'`, it returns `1` without throwing.
* It logs **`"A2"`** and returns `<p>1</p>`.
