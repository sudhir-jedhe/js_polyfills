***  17. flushSync().md ***

```js
// This is a React Quiz from BFE.dev


import * as React from 'react'
import { useState } from 'react'
import { createRoot, flushSync } from 'react-dom/client'
import { screen, fireEvent } from "@testing-library/dom";

function App() {
  const [state, setState] = useState(0)
  const onClick = () => {
    console.log('handler')
    flushSync(() => {
      setState(state => state + 1)
    })
    console.log('handler ' + state)
  }
  console.log('render ' + state)
  return <div>
    <button onClick={onClick}>click me</button>
  </div>
}

const root = createRoot(document.getElementById("root"));
root.render(<App />);

(async function () {
  const action = await screen.findByText('click me')
  fireEvent.click(action);
})()


    
```

```text
"render 0"
"handler"
"render 1"
"handler 0"

```

### Step-by-Step Breakdown

**1. Initial Render (`state = 0`)**

* `App` initializes `state` to `0`.
* `console.log('render ' + state)` runs during the initial render and logs **`"render 0"`**.

**2. Button Click Handler**

* When the button is clicked, `onClick` executes:
* `console.log('handler')` executes first and logs **`"handler"`**.
* `flushSync(...)` forces React to interrupt the normal batching flow and synchronously flush the state update and re-render immediately:
* `App` re-renders synchronously with `state = 1`.
* During this re-render, `console.log('render ' + state)` executes and logs **`"render 1"`**.
* React commits the DOM update and returns from `flushSync`.

* The handler resumes: `console.log('handler ' + state)` reads `state` from the current closure scope (which captured `state = 0` during the initial render) and logs **`"handler 0"`**.
