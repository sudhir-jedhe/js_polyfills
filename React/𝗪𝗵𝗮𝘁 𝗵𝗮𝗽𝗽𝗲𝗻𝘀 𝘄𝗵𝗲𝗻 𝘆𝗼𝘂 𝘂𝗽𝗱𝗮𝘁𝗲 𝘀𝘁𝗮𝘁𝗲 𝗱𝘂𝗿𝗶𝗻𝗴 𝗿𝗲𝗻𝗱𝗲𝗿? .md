Updating state directly inside the render phase (in the component body before returning JSX) causes one of two outcomes depending on whether the update is unconditional or guarded:

---

**1. Unconditional Update: Immediate Infinite Crash**

If you call `setState` directly in the component body without conditions, React attempts to re-render immediately. This triggers another `setState`, rapidly exceeding the maximum update limit:

```jsx
function BadCounter() {
  const [count, setCount] = useState(0);

  // ❌ Crash: Triggers an immediate re-render on every execution
  setCount(count + 1);

  return <div>{count}</div>;
}

```

* **Result:** React crashes and throws `Too many re-renders. React limits the number of renders to prevent an infinite loop.` (or `Maximum update depth exceeded`).

---

**2. Guarded Update: Synchronous State Adjustment (Valid Pattern)**

If you call `setState` inside a strict conditional check based on props, React **aborts the current render** and immediately re-runs the component with the new state *before* rendering children or committing changes to the DOM.

```jsx
function Counter({ initialCount }) {
  const [prevCount, setPrevCount] = useState(initialCount);
  const [count, setCount] = useState(initialCount);

  // ✅ Allowed: Adjusting state based on props change
  if (initialCount !== prevCount) {
    setPrevCount(initialCount);
    setCount(initialCount); // Re-renders synchronously with new state
  }

  return <div>{count}</div>;
}

```

* **Behavior:** React stops the render pass as soon as `setState` is called and restarts it with the updated state.
* **Why it's rarely needed:** Calculating the value directly during render (derived state) or resetting component state using a `key` prop on the parent is almost always cleaner and faster.

---

**Summary of Render-Time State Updates**

| Execution Context                 | React Behavior                                     | Outcome                                        |
| --------------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| **Unconditional in Body**         | Endless re-render recursion                        | Application crashes with `Too many re-renders` |
| **Guarded by Condition (`if`)**   | Discards current pass; immediately restarts render | Synchronous update without DOM commit          |
| **Inside Event Handler / Effect** | Scheduled update after render phase                | Standard React lifecycle flow                  |
