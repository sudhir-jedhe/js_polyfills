React determines whether to re-render using **`Object.is()` shallow equality comparison**. If a component re-renders despite the data looking identical, it is usually due to reference inequality, parent re-renders, or context updates.

**1. Object & Array Reference Inequality (New Memory Addresses)**

Primitives (`number`, `string`, `boolean`) compare by value, but objects, arrays, and functions compare by **reference**. Setting state with a newly instantiated object or array will always trigger a re-render—even if its internal values are identical.

```jsx
// ❌ Re-renders every time because a new object reference is created
setUser({ name: 'Alex' }); 

// Object.is({ name: 'Alex' }, { name: 'Alex' }) === false

```

---

**2. Parent Component Re-rendered**

By default, when a parent component re-renders, **all of its child components re-render**, regardless of whether their props or internal state changed.

* **Fix:** Wrap the child in `React.memo` and wrap passed functions/objects in `useCallback` and `useMemo`.

```jsx
const Child = React.memo(function Child({ onClick }) {
  return <button onClick={onClick}>Click me</button>;
});

```

---

**3. Non-Memoized Complex Props (Functions, Objects, Arrays)**

If a parent creates inline objects or functions, it generates new memory references on every render, invalidating `React.memo` on the child.

```jsx
function Parent() {
  // ❌ New function reference created on EVERY Parent render
  const handleClick = () => console.log('clicked'); 

  return <Child onClick={handleClick} />;
}

// ✅ Fix: Memoize the callback reference
function Parent() {
  const handleClick = useCallback(() => console.log('clicked'), []);
  return <Child onClick={handleClick} />;
}

```

---

**4. Context Value Updates**

If a component consumes a context (`useContext`), it will re-render whenever the context provider's `value` prop receives a new reference, even if the component only cares about an unchanged property inside that context.

```jsx
// Provider passing a non-memoized object:
<AuthContext.Provider value={{ user, theme }}> 
  {/* All consuming children re-render on any Provider render */}
</AuthContext.Provider>

// ✅ Fix: Memoize the provider value
const value = useMemo(() => ({ user, theme }), [user, theme]);
return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;

```

---

**5. Direct State Mutation (The Bailing-Out Trap)**

Mutating state directly and passing the same object back bypasses React's change detection or causes unexpected rendering states:

```jsx
// ❌ Direct mutation: React compares old and new state references
user.name = 'John';
setUser(user); // Same reference! React may bail out now, but fail to render changes later.

```

---

**Quick Diagnosis Checklist**

| Reason                          | Root Cause                           | Solution                                                                           |
| ------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------- |
| **Same values in object/array** | New object literal created (`{...}`) | Keep previous reference if unchanged, or compare fields before calling `setState`. |
| **Parent rendered**             | Default cascading render tree        | Wrap child in `React.memo`.                                                        |
| **Handler prop changed**        | Function recreated on parent render  | Wrap handler in `useCallback`.                                                     |
| **Context consumer**            | Provider value changed reference     | Split contexts or wrap provider `value` in `useMemo`.                              |
