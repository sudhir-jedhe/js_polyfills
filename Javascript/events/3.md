**1. React Fiber Tree Event Dispatch Architecture**

React's event system operates as a synthetic layer built directly over the host DOM.

* **Fiber Node Association:** Every rendered DOM node maintains an internal reference to its corresponding Fiber node via internal properties (e.g., `__reactFiber$...` and `__reactProps$...`).
* **Root Container Delegation:** During application initialization (`createRoot(container)`), React attaches listeners for all supported native events to the root DOM container (e.g., `<div id="root">`).
* **Two-Pass Path Reconstruction:**

1. **Capture Phase:** When an event fires, React grabs the native event target, looks up its Fiber node, and walks up the `return` (parent) pointers to the root, collecting all `onClickCapture`-style listeners. React invokes these top-down.
2. **Bubble Phase:** React traverses the path back down (or iterates the collected array in reverse), invoking standard `onClick` listeners bottom-up.

* **Batching Integration:** Event dispatches execute inside React's scheduler batching context (e.g., `batchedUpdates`), ensuring that multiple state updates triggered within a single event callback are grouped into a single render cycle.

```
Native Click on <button>
       │
       ▼ (Bubbles via Native DOM)
Root Container (#root) ───► Native Listener Fires
                                  │
                                  ▼
                     Target Fiber Identified
                                  │
      ┌───────────────────────────┴───────────────────────────┐
      ▼                                                       ▼
1. Traverse Up (Capture Pass)               2. Traverse Up (Bubble Pass)
   Execute `onClickCapture` props              Execute `onClick` props
   (Root ──► Button)                           (Button ──► Root)

```

**2. Custom Event Creation and Dispatching in Vanilla JS**

Vanilla JavaScript provides the `CustomEvent` constructor and the `dispatchEvent` method to build decoupled, event-driven architectures.

* **Syntax & Configuration:**

```javascript
const userLoginEvent = new CustomEvent('user:login', {
  detail: { userId: 'usr_8492', role: 'admin' }, // Custom payload
  bubbles: true,                                  // Allow event to bubble up DOM tree
  cancelable: true,                               // Allow listeners to call e.preventDefault()
  composed: true                                  // Allow crossing Shadow DOM boundary
});

```

* **Dispatching & Listening:**

```javascript
const element = document.querySelector('#auth-container');

// Add listener
document.addEventListener('user:login', (e) => {
  console.log(`User logged in: ${e.detail.userId}`);
  if (e.detail.role !== 'superadmin') {
    e.preventDefault(); // Marks the event as defaultPrevented
  }
});

// Dispatch event
const wasNotCancelled = element.dispatchEvent(userLoginEvent);
if (!wasNotCancelled) {
  console.log('Action was canceled by a listener via preventDefault()');
}

```

**3. Passive Event Listeners & Scroll Performance Optimization**

During touch and scroll interactions (`touchstart`, `touchmove`, `wheel`, `scroll`), browsers traditionally pause scrolling on the main thread until event listeners finish executing, just in case the listener calls `event.preventDefault()`.

* **The Problem (Jank/Lag):** This blocking mechanism delays compositing, resulting in stuttering and low frame rates during fast scrolling or gestures.
* **The Solution (`{ passive: true }`):** Passing `{ passive: true }` signals to the browser engine that the handler **will never call `preventDefault()**`. This allows the compositor thread to scroll immediately without waiting for JavaScript execution on the main thread.

```javascript
// High-performance touch and wheel listeners
window.addEventListener('touchmove', handleTouchMove, { passive: true });
window.addEventListener('wheel', handleWheelScroll, { passive: true });

```

* **Constraints:** If `event.preventDefault()` is invoked inside a passive listener, the browser ignores it and outputs a console warning.
* **Default Browser Behavior:** In modern browsers, `touchstart` and `touchmove` listeners attached to `window`, `document`, or `body` default to `passive: true` automatically.
