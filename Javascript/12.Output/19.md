### 1. Using `var`

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}

```

**Output (after 1 second):**

```text
3
3
3

```

* **Why:** `var` is **function/globally scoped**, meaning there is only **one shared `i` variable** in memory.
* The loop runs synchronously to completion ($i$ becomes `3`), and only *after* that do the asynchronous `setTimeout` callbacks run and read the shared variable `i` (which is now `3`).

---

### 2. Using `let`

```javascript
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}

```

**Output (after 1 second):**

```text
0
1
2

```

* **Why:** `let` is **block-scoped**. For each iteration of the loop, JavaScript creates a **new binding/lexical environment** for `i`.
* Each `setTimeout` callback forms a closure over its own unique instance of `i` at that specific iteration.

---

### 3. Fixing `var` with an IIFE (ES5 Solution)

If you must use `var`, create a separate function scope (closure) manually using an Immediately Invoked Function Expression:

```javascript
for (var i = 0; i < 3; i++) {
  (function (currentI) {
    setTimeout(() => {
      console.log(currentI);
    }, 1000);
  })(i);
}
// Output: 0, 1, 2

```
