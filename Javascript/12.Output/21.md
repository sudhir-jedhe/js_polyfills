### Code Snippet

```javascript
var length = 20;

function count() {
  console.log(this.length);
}

const data = [count, "A", 0];

data[0]("Hey!");

```

---

### Output

```text
3

```

---

### Why this happens

* **Method Invocation:** Calling `data[0]("Hey!")` accesses the function at index `0` and invokes it directly from the `data` array object.
* **Implicit `this` Binding:** When a function is invoked as a method of an array or object, JavaScript binds `this` to the object preceding the bracket/dot notation—here, the `data` array itself.
* **Property Lookup:** `this.length` evaluates to `data.length`.
* Since `data` has three elements (`[count, "A", 0]`), its length is **`3`**. The global variable `var length = 20` is bypassed.

### Code Snippet

```javascript
function sum(a = 10, b = 10) {
  return a + b;
}

console.log(sum());
console.log(sum(1, null));

```

---

### Output

```text
20
1

```

---

### Why this happens

1. **`sum()`:**

* No arguments are provided, so both `a` and `b` default to `undefined`.
* When parameter values are `undefined`, JavaScript triggers the default values: `a = 10` and `b = 10`.
* Result: $10 + 10 = \mathbf{20}$.

1. **`sum(1, null)`:**

* `a` is explicitly passed as `1`.
* `b` is explicitly passed as `null`. Default parameters **only trigger for `undefined**`, so `b` stays `null` instead of falling back to `10`.
* During addition (`1 + null`), JavaScript coerces `null` to the number `0`.
* Result: $1 + 0 = \mathbf{1}$.

[] + [[]] + !![]

The expression evaluates to the string **`"true"`**.

---

### Step-by-Step Breakdown

1. **Evaluate each operand:**

* `[]` converts to primitive string via `.toString()` $\rightarrow$ `""` (empty string)
* `[[]]` converts to primitive string via `.toString()` $\rightarrow$ `""` (empty string)
* `!![]`: Objects/arrays in JavaScript are truthy. `![]` is `false`, and `!false` is **`true`** (boolean).

1. **Evaluate left-to-right additions:**

* Step 1: `[] + [[]]` $\rightarrow$ `"" + ""` $\rightarrow$ `""`
* Step 2: `"" + !![]` $\rightarrow$ `"" + true` $\rightarrow$ **`"true"`** (string)

Here is what happens when you run `console.log(res())` for each case:

---

### Case 1: `let res = () => 21`

```javascript
let res = () => 21;
console.log(res()); // Output: 21

```

* **Why:** Arrow functions with concise bodies (no curly braces `{}`) implicitly return the evaluated expression.

---

### Case 2: `let res = () => {a: 1}`

```javascript
let res = () => {a: 1};
console.log(res()); // Output: undefined

```

* **Why:** The engine interprets the curly braces `{ ... }` as a **function body block**, not an object literal.
* Inside the block, `a:` is treated as a statement label and `1` is an expression statement.
* Because there is no explicit `return` keyword, the function returns **`undefined`**.

---

### Case 3: `let res = () => ({a: 1})`

```javascript
let res = () => ({a: 1});
console.log(res()); // Output: { a: 1 }

```

* **Why:** Wrapping the object literal in parentheses `({ ... })` tells the JavaScript parser to treat the curly braces as an **expression** instead of a code block, resulting in the object being implicitly returned.

---

### Summary Table

| Syntax           | `res()` Output  | Reason                                                         |
| ---------------- | --------------- | -------------------------------------------------------------- |
| `() => 21`       | **`21`**        | Implicit return of literal                                     |
| `() => {a: 1}`   | **`undefined`** | Parsed as code block with a labeled statement (`a:`)           |
| `() => ({a: 1})` | **`{ a: 1 }`**  | Parentheses force parser to treat `{}` as an object expression |

### Code Snippet

```javascript
class Person {
  constructor(name) {
    this.name = name;
  }

  showName() {
    console.log(this.name);
  }
}

const hero = new Person('Mr.X');
const fn = hero.showName;
fn();

```

---

### Output

```text
TypeError: Cannot read properties of undefined (reading 'name')

```

---

### Why this happens

1. **Class bodies execute in strict mode:** The body of any ES6 `class` is implicitly evaluated in strict mode (`"use strict"`), even if `"use strict"` isn't written explicitly.
2. **Loss of `this` context:**

* When assigning `hero.showName` to a standalone variable `fn`, only the reference to the function itself is copied, detaching it from the `hero` instance.

1. **Default `this` binding in strict mode:**

* When `fn()` is invoked as a plain function call (without an object preceding it like `hero.showName()`), `this` defaults to **`undefined`** rather than the global `window`/`global` object.
* Accessing `this.name` becomes `undefined.name`, throwing a `TypeError`.

---

### How to Fix It

**1. Using `.bind()`:**

```javascript
const fn = hero.showName.bind(hero);
fn(); // "Mr.X"

```

**2. Using Class Field Arrow Function:**

```javascript
class Person {
  constructor(name) {
    this.name = name;
  }

  showName = () => {
    console.log(this.name);
  };
}

```

**3. Invoking within an Arrow Wrapper:**

```javascript
const fn = () => hero.showName();
fn(); // "Mr.X"

```

### Code Snippet

```javascript
function magic() {
  return x = 1, [], {};
}

console.log(magic());

```

---

### Output

```javascript
{}

```

---

### Why this happens

1. **The Comma Operator (`,`)**:

* Evaluates expressions sequentially from **left to right** and returns the value of the **last expression**.

1. **Step-by-step evaluation inside `return**`:

* First: `x = 1` executes (in sloppy mode, this assigns `1` to global variable `x`).
* Second: `[]` evaluates to an empty array.
* Last: `{}` evaluates to an empty object literal.

1. Because `{}` is the final expression in the comma chain, the `return` statement returns `{}`.
