### Why this happens (Logical AND `&&`)

* **Short-Circuit Evaluation:** The logical AND (`&&`) operator evaluates operands from left to right.
* If the first operand is **falsy**, it short-circuits and immediately returns that first operand.
* If the first operand is **truthy**, it continues and evaluates/returns the **second operand** regardless of its value.

* Since `IG` (`"Allahabadi.dev"`) is a non-empty string (truthy), the evaluation moves to `YT` and returns `"FrontendMaster"`.

### Why this happens

1. **Hoisting Phase (Creation Phase):**

* Both the function declaration `function magic() { ... }` and the variable declaration `var magic` are hoisted.
* In JavaScript, function declarations hoist **first** with their full definition.
* The `var magic` declaration points to the same name and is effectively ignored during hoisting because `magic` is already defined as a function.

1. **Execution Phase (Runtime):**

* Line 1 executes: `magic = 1;`. The variable `magic` (which was the function) is now reassigned to the number `1`.
* Line 2–4 (`function magic() {...}`) was already handled during hoisting and skipped at runtime.
* Line 5 executes: `magic()`. Since `magic` is currently the primitive number `1`, invoking it as a function (`1()`) throws a **`TypeError: magic is not a function`**.

1. **Why TypeScript flags "Duplicate identifier":**

* TypeScript and static analysis tools strictly disallow declaring a variable and a function with the identical identifier in the same scope to prevent this exact runtime failure.

1. `let b = a++` $\rightarrow$ The postfix increment evaluates to the current value of `a` (which is `10`) and assigns it to `b`, then increments `a` to `11`.
2. `a = 11`, `b = 10`.
3. `a + b = 11 + 10 = 21`.

* **Output:** `21`

### 5. String Immutability (`8.51.49 PM.png`)

```javascript
let name = "JS";
```

### 7. Prefix vs. Postfix Increment Operator (`8.52.54 PM.png`)

```javascript
let num = 1;

const sum = ++num + num++;

console.log(sum);

```

* **Step-by-step:**

1. `++num` (Prefix): Increments `num` to `2` first, evaluates to `2`.
2. `+` operator.
3. `num++` (Postfix): Evaluates to the current value of `num` (`2`), then increments `num` to `3`.
4. `sum = 2 + 2 = 4`.

* **Output:** `4`

### 8. Implicit String Coercion & Left-to-Right Evaluation (`8.53.01 PM.png`)

```javascript
console.log("2" + 1 + 1);
console.log(2 + 1 + "1");

```

* **Line 1 (`"2" + 1 + 1`):**
* Evaluates left to right: `"2" + 1` triggers string concatenation $\rightarrow$ `"21"`.
* `"21" + 1` triggers string concatenation $\rightarrow$ `"211"`.

* **Line 2 (`2 + 1 + "1"`):**
* Evaluates left to right: `2 + 1` performs numeric addition $\rightarrow$ `3`.
* `3 + "1"` triggers string concatenation $\rightarrow$ `"31"`.

* **Output:**

```text
211
31
```

### 9. Event Trustworthiness (`event.isTrusted`) (`8.54.04 PM.png`)

```javascript
function pay(event) {
  if (event.isTrusted) {
    alert("1000INR Paid.💰");
  } else {
    alert("Fraud Alert 🙅‍♀️");
  }
}

```

* **Core Concept:** `event.isTrusted` is a read-only boolean property provided by the browser:
* **`true`:** The event was initiated by an actual human user interaction (e.g., real mouse click or key press).
* **`false`:** The event was synthetic or programmatic (e.g., triggered via `element.click()`, `dispatchEvent()`, or automated bot scripts).

* **Takeaway:** It provides client-side protection against unauthorized bot clicks/scripted payments.
