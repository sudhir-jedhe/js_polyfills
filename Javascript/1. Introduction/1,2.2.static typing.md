A **type system** is a set of rules that programming languages use to assign properties (types) to variables, expressions, functions, and objects. The core distinction between **Dynamic** and **Static** type systems lies in **when** type checking occurs: at runtime or at compile-time.

---

### Core Comparison

| Dimension                  | Static Type System                                                | Dynamic Type System                                        |
| -------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------- |
| **When Types are Checked** | **Compile-time** (before execution)                               | **Runtime** (during execution)                             |
| **Type Binding**           | Variables are bound to a specific type                            | Values have types; variables are just references           |
| **Error Detection**        | Catches type mismatches early during build/compilation            | Type errors surface when the specific code path runs       |
| **Performance**            | Faster execution (compiler optimizes memory and CPU instructions) | Slower execution (requires runtime type inspection/boxing) |
| **Refactoring & Tooling**  | Reliable autocomplete, jump-to-definition, automated refactoring  | Flexible, but relies heavily on runtime test coverage      |
| **Examples**               | TypeScript, Java, Rust, Go, C++                                   | JavaScript, Python, Ruby, PHP                              |

---

### Dynamic Type Systems

In dynamic languages, types are associated with **values**, not variable declarations. A single variable identifier can hold a string, then a number, then an object.

```javascript
// JavaScript (Dynamically Typed)
let data = "hello"; // typeof data === "string"
data = 42;          // typeof data === "number" (valid at runtime)

function calculate(a, b) {
  return a.total + b; // If 'a' is null or lacks 'total', fails at RUNTIME
}

// Throws TypeError only when executed:
calculate(null, 5); // Uncaught TypeError: Cannot read properties of null

```

**Key Characteristics:**

* **Duck Typing:** *"If it walks like a duck and quacks like a duck, it's a duck."* Functions focus on whether an object has the required property/method at execution time, not its formal inheritance.
* **Rapid Prototyping:** Less boilerplate allows faster initial development and scripting.
* **Risk:** Unhandled edge cases (e.g., passing `undefined` into a deep helper) can reach production unless covered by tests.

---

### Static Type Systems

In static languages, types are associated with the **variable bindings and expressions**. Type checking happens ahead of time.

```typescript
// TypeScript (Statically Typed layer over JS)
let data: string = "hello";
// data = 42; 
// ❌ Compile Error: Type 'number' is not assignable to type 'string'.

interface Order {
  total: number;
}

function calculate(a: Order, b: number): number {
  return a.total + b;
}

// ❌ Compile Error before code even runs:
// calculate(null, 5); // Argument of type 'null' is not assignable to parameter of type 'Order'.

```

**Key Characteristics:**

* **Compile-Time Verification:** Entire classes of bugs (typos in property names, missing parameters, `null`/`undefined` dereferencing) are eliminated before deployment.
* **Self-Documenting Code:** Types serve as living API contracts that never go out of sync with implementation.
* **Type Inference:** Modern static languages (TypeScript, Go, Rust) infer types automatically without requiring explicit annotations everywhere (e.g., `let x = 5` infers `number`).

---

### Static vs. Dynamic $\neq$ Strong vs. Weak

It is common to confuse **Static/Dynamic** (when types are checked) with **Strong/Weak** (how strictly type conversions are enforced):

```
                     STATIC                        DYNAMIC
          ┌───────────────────────────┬───────────────────────────┐
          │                           │                           │
  STRONG  │  Java, Rust, Go, Swift    │  Python, Ruby             │
          │  (Checked at compile time,│  (Checked at runtime,     │
          │   no implicit coercion)   │   no implicit coercion)   │
          ├───────────────────────────┼───────────────────────────┤
          │                           │                           │
  WEAK    │  C, C++                   │  JavaScript, PHP          │
          │  (Pointers/memory can be  │  ("5" + 2 = "52",         │
          │   reinterpreted freely)   │   coercion rules apply)   │
          └───────────────────────────┴───────────────────────────┘

```

* **Python** is *Dynamic + Strong*: `1 + "2"` throws a runtime `TypeError`.
* **JavaScript** is *Dynamic + Weak*: `1 + "2"` evaluates to `"12"` via implicit coercion.
