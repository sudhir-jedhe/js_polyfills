An **infinite re-render loop** occurs, eventually crashing the component when React hits its maximum update depth safeguard (`Maximum update depth exceeded`).

**The Lifecycle Breakdown**

1. **Initial Render:** The component evaluates its JSX and commits it to the DOM.
2. **Effect Execution:** Because `useEffect` lacks a dependency array, it executes after *every* completed render.
3. **State Mutation:** `setState` triggers an asynchronous state update and queues a new render.
4. **Subsequent Render:** React re-renders the component with the new state.
5. **Loop Repeats:** The post-render cycle triggers `useEffect` again, invoking `setState` and locking the application into an endless cycle.

```jsx
// ❌ Anti-pattern: Triggers an infinite loop
useEffect(() => {
  setCount(count + 1);
}); // Missing dependency array

```

---

**Common Fixes**

* **Run once on mount:** Add an empty dependency array `[]`.

```jsx
useEffect(() => {
  fetchInitialData();
}, []);

```

* **Run conditionally:** Track specific primitive/memoized dependencies.

```jsx
useEffect(() => {
  setCount(userId * 2);
}, [userId]);

```

* **Derive state during render:** If the value depends purely on existing props or state, compute it directly rather than synchronizing it via an effect.

```jsx
const doubleCount = count * 2; // No useEffect needed
```

**The Execution Loop**

**How to Fix It**

* **Run on Mount Only:** Pass an empty dependency array `[]`.

```jsx
useEffect(() => {
  fetchUserData();
}, []); // Runs once after initial mount

```

* **Run on Value Change:** Add specific reactive values to the array.

```jsx
useEffect(() => {
  setFormattedName(user.name.trim());
}, [user.name]); // Runs only when user.name changes

```
