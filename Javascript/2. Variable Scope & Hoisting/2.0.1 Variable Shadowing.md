*** copy 2.0.1 Variable Shadowing.md ***

**Variable Shadowing** occurs when a variable declared in an inner scope (a block or function) has the same name as a variable in an outer scope.

The inner variable **shadows** (hides) the outer variable within that block. The JavaScript engine resolves the identifier to the closest declaration in the scope chain, rendering the outer variable inaccessible by that bare identifier.

---

### Basic Example: Block & Function Shadowing

```javascript
const name = "Global Alice";

function showUser() {
  const name = "Function Bob"; // Shadows outer `name`

  if (true) {
    const name = "Block Charlie"; // Shadows both function and global `name`
    console.log(name); // "Block Charlie" (Closest scope)
  }

  console.log(name); // "Function Bob"
}

showUser();
console.log(name); // "Global Alice"

```

---

### Valid vs. Illegal Shadowing

#### 1. Valid Shadowing Patterns

| Outer Scope     | Inner Scope      | Valid?    | Why                                                                 |
| --------------- | ---------------- | --------- | ------------------------------------------------------------------- |
| `var`           | `let` / `const`  | ✅ **Yes** | Block-scoped declaration is confined inside the block.              |
| `let` / `const` | `let` / `const`  | ✅ **Yes** | Inner block creates an isolated lexical scope.                      |
| `var`           | `var` (Function) | ✅ **Yes** | Inner `var` is bound to the child function's `VariableEnvironment`. |

```javascript
// Valid: let inside block shadows outer var
var status = "active";
{
  let status = "pending"; // ✅ OK: status is scoped to this block
  console.log(status);   // "pending"
}
console.log(status);     // "active"

```

---

#### 2. Illegal Shadowing (`var` crossing block boundaries)

You **cannot** shadow an outer `let` or `const` using a `var` within the same function boundary.

```javascript
let count = 10;

{
  var count = 20; 
  // ❌ SyntaxError: Identifier 'count' has already been declared
}

```

**Why this fails:** `var` does not respect block scopes `{}` and hoists directly to the enclosing function or global scope. Because `let count` already occupies that same function/global lexical environment, the hoisted `var count` causes a compile-time collision.

---

### Shadowing Function Parameters

Function arguments behave like `let` declarations initialized at the function head:

```javascript
function calculate(total) {
  if (true) {
    let total = 50; // ✅ Valid: Shadows the parameter inside the block
    console.log(total); // 50
  }

  console.log(total); // Prints argument passed to calculate()
}

calculate(100);

```

However, redeclaring a parameter using `let` or `const` at the top level of the function body produces an error:

```javascript
function greet(user) {
  let user = "Alice"; 
  // ❌ SyntaxError: Identifier 'user' has already been declared
}

```

### Scope Lookup Mechanism

When evaluating an identifier, the engine walks up the scope chain:

```
[ Current Block Scope ]  ──► Found? ──► Use value & STOP.
          │ (Not found)
          ▼
[ Enclosing Function Scope ] ──► Found? ──► Use value & STOP.
          │ (Not found)
          ▼
[ Global Environment Record ] ──► Found? ──► Use value.
                                  └─► Not found? ──► ReferenceError.

```

Shadowing simply means the lookup finds a match in an early step, so traversal never reaches the outer declarations.
