***  2.14. what is module in js  scope and import expor.md ***

A **JavaScript Module (ES Module / ESM)** is a self-contained JavaScript file that encapsulates its own code.

Instead of dumping every variable into the global namespace, modules provide isolated scope and an explicit `import` / `export` mechanism to share code across files.

---

### 1. Module Scope (Zero Global Pollution)

In a regular JavaScript script, top-level variables pollute the global scope (`window` or `globalThis`). In contrast, **modules have their own top-level scope**:

* Variables, functions, and classes declared inside a module are **private by default**.
* Modules always execute in **Strict Mode (`"use strict"`)** automatically.
* Top-level `this` inside a module is `undefined` (not `window`).

```javascript
// mathUtils.js (Module Scope)
const secretFactor = 1.5; // Private to this module

export function multiply(a, b) {
  return a * b * secretFactor;
}

```

---

### 2. Exporting from a Module

There are two primary ways to export values: **Named Exports** and **Default Exports**.

#### A. Named Exports (Multiple per file)

Used when a module provides multiple utilities, functions, or constants.

```javascript
// utils.js
// 1. Inline named exports
export const API_URL = "https://api.example.com";

export function formatCurrency(amount) {
  return `$${amount.toFixed(2)}`;
}

// 2. Export list syntax (with optional renaming)
const helper = () => {};
export { helper as customHelper };

```

#### B. Default Export (Exactly one per file)

Used when a module represents a single primary responsibility (e.g., a React component, a class, or a main function).

```javascript
// UserProfile.js
export default function UserProfile({ name }) {
  return `<div>User: ${name}</div>`;
}

```

#### C. Aggregating / Re-exporting

Used in `index.js` files to create clean entry points:

```javascript
// index.js (Barrel file)
export { multiply } from './mathUtils.js';
export { default as UserProfile } from './UserProfile.js';
export * from './constants.js';

```

---

### 3. Importing into Another Module

#### A. Importing Named Exports

Named imports must use curly braces `{}` and match the exported names (or use `as` to rename):

```javascript
import { API_URL, formatCurrency as format } from './utils.js';

console.log(API_URL);
console.log(format(42));

```

#### B. Importing Default Exports

Default imports do not use curly braces and can be given any local identifier name:

```javascript
import UserProfile from './UserProfile.js';

```

#### C. Namespace Imports (Import Everything)

Imports all named exports as a single object:

```javascript
import * as Utils from './utils.js';

console.log(Utils.API_URL);
console.log(Utils.formatCurrency(50));

```

#### D. Dynamic Imports (`import()`)

Static `import` statements must be placed at the top level of a file. For code-splitting or lazy loading, use dynamic `import()` which returns a Promise:

```javascript
async function loadAnalytics() {
  const { trackEvent } = await import('./analytics.js');
  trackEvent('button_click');
}

```

---

### 4. How to Enable Modules in Runtimes

* **In the Browser:** Add `type="module"` to the `<script>` tag:

```html
<script type="module" src="./main.js"></script>

```

* **In Node.js:**
* Add `"type": "module"` in your `package.json`, or
* Use the `.mjs` file extension (e.g., `server.mjs`).

---

### 5. ES Modules (ESM) vs. CommonJS (CJS)

| Feature               | ES Modules (ESM)                              | CommonJS (CJS - Node.js legacy)          |
| --------------------- | --------------------------------------------- | ---------------------------------------- |
| **Syntax**            | `import` / `export`                           | `const x = require()` / `module.exports` |
| **Parsing**           | **Static** (Analyzed at compile-time)         | **Dynamic** (Evaluated at runtime)       |
| **Tree-Shaking**      | Supported by bundlers (Vite/Webpack)          | Not easily tree-shakeable                |
| **Top-Level `await**` | Native support                                | Not supported (requires async wrappers)  |
| **Bindings**          | **Live bindings** (reflects exported changes) | **Value copies** (cached upon require)   |
