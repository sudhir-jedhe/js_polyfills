# JavaScript `var` Statement

The `var` statement declares **function-scoped** or **globally-scoped** variables, optionally with an initial value.

---

# Syntax

```js
var name;
var name = value;

var name1 = value1, name2 = value2;
var name1, name2 = value2;

var name1 = value1,
    name2,
    name3 = value3;
```

---

# Basic Example

```js
var x = 1;

if (x === 1) {
  var x = 2;

  console.log(x); // 2
}

console.log(x); // 2
```

### Why?

`var` is **not block scoped**.

The `x` declared inside the `if` block is the same variable as the outer `x`.

---

The reason both `console.log` statements output `2` is because of how the `var` keyword handles **scope**.

In JavaScript, `var` is **function-scoped** (or globally-scoped if it isn't inside a function). Crucially, **it is not block-scoped**. A block is any code wrapped in curly braces `{}`, such as an `if` statement or a `for` loop.

Here is the step-by-step breakdown of exactly what is happening in your code:

1. **`var x = 1;`**
You declare a global variable `x` and assign it the value of `1`.
2. **`if (x === 1) {`**
The condition is true, so the execution enters the `if` block.
3. **`var x = 2;`**
Because `var` ignores block scope, this line **does not** create a new, separate variable named `x` just for the `if` block. Instead, it re-declares and overwrites the exact same `x` you created on line 1.
4. **`console.log(x);`**
This prints the currently assigned value of `x`, which is now `2`.
5. **`console.log(x);` (outside the block)**
Because the original `x` was permanently modified while inside the `if` block, this also prints `2`.

### The Modern Alternative: `let`

If you wanted the `x` inside the `if` statement to be a temporary, isolated variable that does not affect the `x` on the outside, you would use `let` or `const`.

Unlike `var`, `let` **is** block-scoped:

```javascript
let x = 1;

if (x === 1) {
  let x = 2; // This 'x' only exists inside these curly braces

  console.log(x); // Outputs: 2
}

console.log(x); // Outputs: 1 (The outer 'x' was never touched)

```

# Scope Rules

A `var` variable is scoped to:

1. Function body
2. Static initialization block
3. Global scope (in script mode)
4. Module scope (in ES modules)

## Function Scope

```js
function foo() {
  var x = 1;

  function bar() {
    var y = 2;

    console.log(x); // 1
    console.log(y); // 2
  }

  bar();

  console.log(x); // 1
  console.log(y); // ReferenceError
}

foo();
```

---

To verify this code, let us trace how the JavaScript engine resolves scopes and identifier lookups step-by-step:

```javascript
function foo() {
  var x = 1;

  function bar() {
    var y = 2;
    console.log(x); // 1
    console.log(y); // 2
  }

  bar();

  console.log(x); // 1
  console.log(y); // ReferenceError
}

foo();

```

---

### Step-by-Step Scope & Execution Trace

1. **Inside `foo()` Scope:**

* `var x = 1;` creates variable `x` inside `foo`'s Environment Record.
* `bar()` is defined inside `foo()`, creating a child scope that holds an outer reference pointer `[[Scopes]]` to `foo`'s Environment Record.

1. **Inside `bar()` Execution:**

* `var y = 2;` creates variable `y` in `bar`'s local Environment Record.
* `console.log(x)`: The engine checks `bar`'s local scope, does not find `x`, traverses the **lexical scope chain** to parent scope `foo()`, finds `x = 1`, and logs **`1`**.
* `console.log(y)`: The engine finds `y` in `bar`'s local scope and logs **`2`**.
* `bar()` finishes executing and its execution context is popped off the call stack.

1. **Back in `foo()` Execution:**

* `console.log(x)`: Resolves `x` directly in `foo`'s scope and logs **`1`**.
* `console.log(y)`: The engine looks for `y` in `foo`'s scope $\rightarrow$ not found. It checks the global scope $\rightarrow$ not found.
* Because scope lookup is strictly **one-way (inner to outer)**, `foo` cannot access variables declared inside child function `bar`. The engine throws **`ReferenceError: y is not defined`**.

---

### Scope Hierarchy

```
[ Global Scope ]
       │
       ▼
[ foo() Scope ]  ──► contains: `x = 1`, `bar`
       │
       ▼ (Scope Chain Lookup)
[ bar() Scope ]  ──► contains: `y = 2`

```

---

Your trace and output annotations (`1`, `2`, `1`, and `ReferenceError`) are **completely correct**.

# `var` Ignores Block Scope

```js
if (true) {
  var message = "Hello";
}

console.log(message); // Hello
```

```js
for (var i = 0; i < 3; i++) {}

console.log(i); // 3
```

Unlike `let` and `const`, `var` escapes blocks.

---

# Global Behaviour

In browsers, a top-level `var` becomes a property of `window`/`globalThis`.

```js
var x = 10;

console.log(globalThis.x); // 10
```

```js
delete globalThis.x; // Fails
```

### Important

In ES Modules and Node.js modules:

```js
var x = 10;
```

does **not** create a global property.

---

# Hoisting

`var` declarations are hoisted.

## Example

```js
console.log(a); // undefined

var a = 10;

console.log(a); // 10
```

JavaScript interprets it roughly as:

```js
var a;

console.log(a); // undefined

a = 10;

console.log(a); // 10
```

### Key Point

Only the **declaration** is hoisted.

The **initialisation** is not.

---

# Hoisting Inside Functions

```js
function demo() {
  console.log(count); // undefined

  var count = 100;

  console.log(count); // 100
}

demo();
```

Equivalent to:

```js
function demo() {
  var count;

  console.log(count);

  count = 100;

  console.log(count);
}
```

---

# Redeclaration

`var` allows redeclaration.

```js
var a = 1;
var a = 2;

console.log(a); // 2
```

```js
var a = 1;

var a;

console.log(a); // 1
```

No error occurs.

---

# `var` With Functions

```js
console.log(typeof test); // "function"

function test() {}

var test;

console.log(typeof test); // "function"
```

If later assigned:

```js
var test = 1;

function test() {}

console.log(test); // 1
```

The assignment wins.

---

# `var` Cannot Coexist With `let` or `const`

❌ Invalid

```js
var a = 1;
let a = 2;
```

```js
let a = 1;

{
  var a = 2;
}
```

Both throw:

```txt
SyntaxError: Identifier 'a' has already been declared
```

✅ Valid

```js
var a = 1;

{
  let a = 2;
}
```

Different scopes.

---

# Function Parameters

A parameter and a `var` can share the same name.

```js
function foo(a) {
  var a = 10;

  console.log(a);
}

foo(5); // 10
```

# Multiple Assignments

```js
var x = y,
    y = "A";

console.log(x, y);
```

Output:

```txt
undefined A
```

Because both declarations are hoisted, but assignments happen later.

---

To determine the output of this code, let us trace how the JavaScript engine handles variable hoisting and execution order step-by-step:

```javascript
var x = y,
    y = "A";
console.log(x, y);

```

---

### Step-by-Step Breakdown

1. **Compilation / Creation Phase (Hoisting):**

* The engine scans the current scope and finds the declarations for both `x` and `y`.
* Because they are declared with `var`, both variables are hoisted to the top of the scope and initialized with the value **`undefined`**:
* `x = undefined`
* `y = undefined`

1. **Execution Phase:**

* **`x = y;` runs first:** The engine evaluates the right-hand side (`y`). At this point, `y` holds its hoisted value (`undefined`). Therefore, `x` is assigned **`undefined`**.
* **`y = "A";` runs second:** The variable `y` is assigned the string **`"A"`**.
* **`console.log(x, y);`:** Reads the current values of `x` (`undefined`) and `y` (`"A"`).

---

### Output

```text
undefined A

```

---

### Contrast with `let` / `const`

If this were written with `let` or `const`:

```javascript
let x = y,
    y = "A";

```

The engine would throw a **`ReferenceError: Cannot access 'y' before initialization`** because `y` would be in the **Temporal Dead Zone (TDZ)** when evaluated for `x`.

To analyze what happens when running this code, let us trace how the JavaScript engine handles block-scoped declarations during compilation and execution:

```javascript
let x = y,
    y = "A";

```

---

### Step-by-Step Execution Breakdown

1. **Compilation / Creation Phase (Hoisting & TDZ):**

* The engine scans the current block/scope and registers both identifiers `x` and `y` in the Declarative Environment Record.
* Unlike `var` (which is hoisted and initialized to `undefined`), variables declared with `let` and `const` are **hoisted in an uninitialized state**.
* Both `x` and `y` enter the **Temporal Dead Zone (TDZ)** from the start of the block until their individual declaration statements are reached and evaluated.

1. **Execution Phase:**

* The statement begins evaluating the initializer for `x`: `let x = y`.
* To assign a value to `x`, the engine attempts to read identifier `y`.
* Because the line `y = "A"` has not yet been executed, `y` is still uninitialized and residing in its **Temporal Dead Zone**.
* Accessing an uninitialized `let` variable triggers an immediate runtime exception.

---

### Output / Error

```text
ReferenceError: Cannot access 'y' before initialization

```

---

### Comparison: `var` vs. `let`

```javascript
// 1. Using var: Hoisted and initialized with undefined
var x = y, y = "A";
console.log(x, y); // undefined "A"

// 2. Using let: Hoisted in uninitialized state (TDZ)
let a = b, b = "A"; 
// ❌ ReferenceError: Cannot access 'b' before initialization

```

# Dangerous Pattern: `var x = y = 1`

```js
function demo() {
  var x = y = 1;
}
```

Equivalent to:

```js
y = 1;
var x = y;
```

### Result

```js
function demo() {
  var x = y = 1;
}

demo();

console.log(y); // 1
```

`y` becomes a global variable in non-strict mode.

---

# Strict Mode

```js
"use strict";

function demo() {
  var x = y = 1;
}
```

Throws:

```txt
ReferenceError: y is not defined
```

---

To analyze what happens with this code, let us look at how the JavaScript engine processes and executes it step-by-step:

```javascript
y = 1;
var x = y;

```

---

That is an accurate explanation of one of JavaScript's most common scoping traps.

The chained assignment `var x = y = 1;` executes **right-to-left**, causing unintended global variable leakage.

---

### Step-by-Step Mechanism

```javascript
function demo() {
  var x = (y = 1);
}

```

1. **Right-Hand Evaluation (`y = 1`):**

* The assignment operator (`=`) has right-to-left associativity.
* The engine evaluates `y = 1` first. Because `y` has no `var`, `let`, or `const` keyword attached, the engine searches up the scope chain, fails to find a declaration, and creates `y` as a property on the **global object** (`window.y` or `globalThis.y`).

1. **Left-Hand Evaluation (`var x = ...`):**

* The result of `(y = 1)` is `1`.
* `x` is declared locally to `demo()` using `var` and assigned `1`.

1. **After Function Returns:**

* `x` is trapped inside `demo()`'s local scope and garbage collected.
* `y` remains on the global object, accessible anywhere in the application.

---

### Non-Strict vs. Strict Mode

#### Non-Strict Mode (Silent Leak)

```javascript
function demo() {
  var x = y = 1;
}
demo();

console.log(globalThis.y); // 1 (Global polluted)
// console.log(x);        // ReferenceError: x is not defined (Correctly local)

```

#### Strict Mode (Immediate Safety Error)

In `"use strict";`, assigning to an undeclared identifier is prohibited and fails fast:

```javascript
function demo() {
  "use strict";
  var x = y = 1; // ❌ ReferenceError: y is not defined
}
demo();

```

---

### The Safe Alternatives

```javascript
// 1. Explicit multi-declaration with let/const
function safeDemo() {
  let x = 1, y = 1; // Both are strictly local
}

// 2. Separate lines
function safeDemo2() {
  const y = 1;
  const x = y;
}

```

### Step-by-Step Execution Breakdown

1. **Compilation Phase (Hoisting):**

* The engine scans the scope and finds `var x`.
* The declaration of `x` is hoisted to the top of the enclosing function/global scope and initialized with `undefined`.
* `y` has no `var`, `let`, or `const` keyword attached, so it is **not hoisted**.

1. **Execution Phase:**

* **Line 1 (`y = 1;`):**
* **In Non-Strict Mode:** The engine looks for `y` in the scope chain. Finding no declaration, it creates `y` as a property on the global object (`globalThis.y = 1`).
* **In Strict Mode (`"use strict";`):** The engine throws a **`ReferenceError: y is not defined`** immediately because assigning to an undeclared identifier is prohibited.

* **Line 2 (`var x = y;`):**
* In non-strict mode, `y` resolves to `1`.
* `x` is assigned `1`.

---

### Verification & Output

```javascript
y = 1;
var x = y;

console.log(x); // 1
console.log(y); // 1
console.log(globalThis.y); // 1 (Implicit global)

```

---

### Summary of Differences Between `x` and `y`

| Variable             | Hoisted?               | Scope / Storage                            | Deletable via `delete`?            |
| -------------------- | ---------------------- | ------------------------------------------ | ---------------------------------- |
| **`x`** (`var`)      | ✅ Yes (as `undefined`) | Function / Global Scope (non-configurable) | ❌ `delete x` $\rightarrow$ `false` |
| **`y`** (Undeclared) | ❌ No                   | Global Object property (configurable)      | ✅ `delete y` $\rightarrow$ `true`  |

# Implicit Globals

```js
var x = 0;

function a() {
  var y = 2;

  function b() {
    x = 3;
    y = 4;
    z = 5;
  }

  b();

  console.log(x, y, z); // 3 4 5
}

a();

console.log(x, z); // 3 5
```

`z` becomes global because it was assigned without declaration.

---

That is spot-on. This snippet is a classic demonstration of how JavaScript resolves variable assignments through the scope chain and creates an **implicit global** when no declaration exists.

---

### Step-by-Step Scope Resolution

```javascript
var x = 0;

function a() {
  var y = 2;

  function b() {
    x = 3;
    y = 4;
    z = 5;
  }

  b();
  console.log(x, y, z); // 3 4 5
}

a();
console.log(x, z); // 3 5

```

1. **Resolving `x = 3`:**

* Looks inside `b()` $\rightarrow$ Not found.
* Traverses up to `a()` $\rightarrow$ Not found.
* Traverses up to the global scope $\rightarrow$ Finds `var x`.
* Mutates the global variable `x` from `0` to `3`.

1. **Resolving `y = 4`:**

* Looks inside `b()` $\rightarrow$ Not found.
* Traverses up to `a()` $\rightarrow$ Finds `var y`.
* Mutates the local variable `y` inside `a()` from `2` to `4`.

1. **Resolving `z = 5`:**

* Looks inside `b()` $\rightarrow$ Not found.
* Looks inside `a()` $\rightarrow$ Not found.
* Looks in the global scope $\rightarrow$ Not found.
* **In Non-Strict Mode:** Since no declaration is found anywhere in the scope chain, JavaScript creates `z` as a property directly on the global object (`globalThis.z = 5` / `window.z = 5`).

---

### After Function `a()` Completes

| Variable | Scope Location                           | Accessible Outside `a()`?                 | Value Outside `a()` |
| -------- | ---------------------------------------- | ----------------------------------------- | ------------------- |
| **`x`**  | Global scope (`var x`)                   | ✅ Yes                                     | `3`                 |
| **`y`**  | Function scope of `a()`                  | ❌ No (`ReferenceError: y is not defined`) | Inaccessible        |
| **`z`**  | Global object property (Implicit Global) | ✅ Yes                                     | `5`                 |

---

### Why Strict Mode Eliminates This

In strict mode (`"use strict";`), assigning to an undeclared identifier halts execution immediately rather than polluting the global namespace:

```javascript
function a() {
  "use strict";
  function b() {
    z = 5; // ❌ ReferenceError: z is not defined
  }
  b();
}

```

# Destructuring With `var`

```js
const result = /(a+)(b+)(c+)/.exec("aaabcc");

var [, a, b, c] = result;

console.log(a); // "aaa"
console.log(b); // "b"
console.log(c); // "cc"
```

# `var` vs `let` vs `const`

| Feature                   | var             | let       | const     |
| ------------------------- | --------------- | --------- | --------- |
| Scope                     | Function        | Block     | Block     |
| Hoisted                   | ✅               | ✅         | ✅         |
| Access before declaration | `undefined`     | TDZ Error | TDZ Error |
| Redeclaration             | ✅               | ❌         | ❌         |
| Reassignment              | ✅               | ✅         | ❌         |
| Becomes global property   | ✅ (script mode) | ❌         | ❌         |

# Interview Summary

```txt
1. var is function-scoped, not block-scoped.
2. var is hoisted and initialised with undefined.
3. var allows redeclaration.
4. Top-level var becomes a global object property in script mode.
5. var x = y = 1 can accidentally create a global variable.
6. Prefer let and const in modern JavaScript.
7. Use var only when maintaining legacy code.
```
