In JavaScript, **mutable** means that a value or data structure's internal contents can be changed after it is created **without creating an entirely new value in memory**.

---

### Mutable vs. Immutable Types

JavaScript types are divided into two fundamental memory categories:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. Immutable (Primitives)                                   │
│    • Stored by VALUE in memory                              │
│    • Cannot be altered in-place                             │
│    • string, number, boolean, null, undefined, symbol,      │
│      bigint                                                 │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 2. Mutable (Reference Types)                                │
│    • Stored by REFERENCE in memory                          │
│    • Can be mutated in-place                                │
│    • Objects (`{}`), Arrays (`[]`), Functions, Maps, Sets   │
└─────────────────────────────────────────────────────────────┘

```

---

### 1. How Mutation Works in Reference Types

When you modify an object or array, you mutate the data in the existing memory heap location:

```javascript
// Arrays are mutable
const numbers = [1, 2, 3];
numbers.push(4);      // Mutated in-place
numbers[0] = 99;      // Mutated in-place

console.log(numbers); // [99, 2, 3, 4] (Same array reference)

// Objects are mutable
const user = { name: "Alice" };
user.name = "Bob";    // Mutated property
user.age = 30;        // Added property

console.log(user);    // { name: "Bob", age: 30 }

```

---

### 2. The Mutation Side Effect (Shared References)

Because mutable objects are passed by reference (pointing to the same memory address), mutating an object through one variable affects all other variables pointing to that same reference:

```javascript
const original = { theme: "light" };
const copy = original; // Copies the REFERENCE, not the data

copy.theme = "dark";   // Mutates the shared object

console.log(original.theme); // "dark" (Unintended side effect!)

```

---

### 3. Contrast: Primitives are Immutable

Primitives cannot be modified in place. Operations that appear to change them actually return a **new value**:

```javascript
let str = "hello";

// Attempting to mutate an index fails silently (or throws in strict mode)
str[0] = "H";
console.log(str); // "hello" (Unchanged)

// String methods return a NEW string; they do not mutate `str`
const upper = str.toUpperCase();
console.log(str);   // "hello" (Original remains untouched)
console.log(upper); // "HELLO" (New memory allocation)

```

---

### Summary: Array Method Mutability Cheat Sheet

This is an excellent cheat sheet structure. JavaScript's array methods are heavily split between those that alter the original array (mutating) and those that return a brand new array (immutable).

Here is your **Array Method Mutability Cheat Sheet**, cleanly organized for quick reference:

| Operation Type               | Mutable (Modifies in-place)               | Immutable (Returns new copy)                           |
| ---------------------------- | ----------------------------------------- | ------------------------------------------------------ |
| **Adding / Removing**        | `push()`, `pop()`, `shift()`, `unshift()` | `concat()`, `[...arr, item]`, `slice()`                |
| **Reordering / Modifying**   | `sort()`, `reverse()`, `splice()`         | `toSorted()`, `toReversed()`, `toSpliced()`            |
| **Transforming / Filtering** | `fill()`, `copyWithin()`                  | `map()`, `filter()`, `reduce()`, `flat()`, `flatMap()` |
| **Replacing at Index**       | `arr[index] = value`                      | `with(index, value)`                                   |

### The "Copying" Counterparts (Introduced in ES2023)

Historically, you had to manually copy an array (e.g., `[...arr].sort()`) to avoid mutating it when sorting or reversing. The newest methods (the `to...` prefix and `with()`) do this automatically:

* **`toSorted()`**: Returns a new sorted array.
* **`toReversed()`**: Returns a new reversed array.
* **`toSpliced()`**: Returns a new array with elements removed/replaced.
* **`with()`**: Returns a new array with a specific index replaced (e.g., `arr.with(1, "newVal")` instead of `arr[1] = "newVal"`).        |

In JavaScript, **`const` prevents variable reassignment**, but it **does not make objects immutable**. To make object values immutable, you must use methods like `Object.freeze()`, `Object.seal()`, or deep-freezing utilities.

---

### 1. `const`: Immutable Variable Binding (Not Value)

`const` creates an immutable binding to a memory address. It prevents reassigning the variable identifier to a new value, but properties inside a reference object can still be mutated.

```javascript
const user = { name: "Alice", age: 25 };

// ❌ Reassignment is blocked:
user = { name: "Bob" }; // TypeError: Assignment to constant variable.

// ✅ Internal property mutation is ALLOWED:
user.age = 26;
user.role = "Admin";
delete user.name;

console.log(user); // { age: 26, role: 'Admin' }

```

### 2. Making Objects Immutable: Methods Comparison

JavaScript provides native `Object` methods with increasing levels of immutability:

| Method                              | Add New Properties? | Delete Properties? | Modify Existing Values? | Reconfigure Descriptors? |
| ----------------------------------- | ------------------- | ------------------ | ----------------------- | ------------------------ |
| **Normal Object**                   | ✅ Yes               | ✅ Yes              | ✅ Yes                   | ✅ Yes                    |
| **`Object.preventExtensions(obj)`** | ❌ No                | ✅ Yes              | ✅ Yes                   | ✅ Yes                    |
| **`Object.seal(obj)`**              | ❌ No                | ❌ No               | ✅ Yes                   | ❌ No                     |
| **`Object.freeze(obj)`**            | ❌ No                | ❌ No               | ❌ No                    | ❌ No                     |

---

### 3. Using `Object.freeze()` (Shallow Immutability)

`Object.freeze()` makes an object's direct properties read-only (`writable: false, configurable: false`):

```javascript
const config = Object.freeze({
  endpoint: "https://api.example.com",
  timeout: 5000,
});

config.timeout = 10000; // Ignored in non-strict mode; throws TypeError in "use strict"
config.retries = 3;     // ❌ Cannot add
delete config.endpoint; // ❌ Cannot delete

console.log(config.timeout); // 5000

```

---

### 4. The Nested Object Trap: Shallow Freezing

`Object.freeze()` only freezes top-level keys. Nested objects remain mutable by default:

```javascript
const profile = Object.freeze({
  name: "Alice",
  preferences: {
    theme: "dark", // Nested reference is NOT frozen
  },
});

profile.preferences.theme = "light"; // ✅ Allowed!
console.log(profile.preferences.theme); // "light"

```

#### Solution: Recursive Deep Freeze Function

```javascript
function deepFreeze(obj) {
  // Retrieve property names
  const propNames = Reflect.ownKeys(obj);

  // Freeze properties before freezing self
  for (const name of propNames) {
    const value = obj[name];
    if (value && typeof value === "object") {
      deepFreeze(value);
    }
  }

  return Object.freeze(obj);
}

const safeProfile = deepFreeze({
  name: "Alice",
  preferences: { theme: "dark" },
});

safeProfile.preferences.theme = "light"; // ❌ Cannot mutate nested values

```

---

### Summary

* **`const`**: Protects the **variable identifier** from reassignment (prevents `user = ...`).
* **`Object.freeze()`**: Protects the **top-level object properties** from mutation, addition, or deletion.
* **`deepFreeze()` / Immutable libraries (e.g., Immer, Immutable.js)**: Protects the **entire nested data structure**.
