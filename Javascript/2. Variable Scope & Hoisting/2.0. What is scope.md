JavaScript has **five main types of scope** that define the accessibility of variables, functions, and objects. Here's a breakdown:

---

### **1. Global Scope**

- Variables declared outside of any function or block are in the global scope.
- They are accessible anywhere in your code.
- In browsers, global variables become properties of the `window` object.

```javascript
var globalVar = "I am global";

function showGlobal() {
  console.log(globalVar); // Accessible
}

console.log(globalVar); // Accessible
```

---
In JavaScript, the **Global Scope** is the outermost execution context. Any variable, function, or object declared outside of all functions and block scopes belongs to the global scope and can be accessed from anywhere in your code.

---

### Key Behaviors: `var` vs. `let` / `const` in Global Scope

How a global variable behaves depends heavily on the keyword used to declare it:

| Feature                                                  | `var` (Global)             | `let` / `const` (Global)           |
| -------------------------------------------------------- | -------------------------- | ---------------------------------- |
| **Accessible Globally?**                                 | Yes                        | Yes                                |
| **Attached to Global Object (`window` / `globalThis`)?** | **Yes**                    | **No**                             |
| **Hoisting Behavior**                                    | Initialized as `undefined` | Uninitialized (Temporal Dead Zone) |
| **Redeclaration Allowed?**                               | Yes                        | No (Throws `SyntaxError`)          |

```javascript
// Browser Environment (Script Mode)
var globalVar = "I am a var";
let globalLet = "I am a let";
const globalConst = "I am a const";

console.log(window.globalVar);   // "I am a var"   (Attached to window)
console.log(window.globalLet);   // undefined       (Lives in Declarative Record)
console.log(window.globalConst); // undefined       (Lives in Declarative Record)

```

---

### The Global Object (`globalThis`)

Each JavaScript runtime provides a global object that hosts built-in APIs (`Math`, `JSON`, `setTimeout`, `fetch`):

- **Browsers:** `window` (or `self` in Web Workers)
- **Node.js:** `global`
- **Universal (ES2020+ standard):** **`globalThis`** (works across Browsers, Node.js, Bun, Deno, and Web Workers)

```javascript
// Universal access across any JS runtime
globalThis.appVersion = "2.4.0";

console.log(appVersion); // "2.4.0"

```

---

### Global Scope in Scripts vs. ES Modules

The concept of "global" changes completely depending on how your code is executed:

- **Classic `<script>` tags:** Top-level variables pollute the shared global environment.
- **ES Modules (`<script type="module">` / `.mjs`):** Top-level declarations are **module-scoped**, not global. They are contained strictly inside that file unless explicitly exported.

```javascript
// Inside an ES Module (or Next.js/Vite/Webpack file):
const apiKey = "12345"; 

// apiKey is ONLY available in this file. It is NOT on window or global scope.

```

---

### The "Implicit Global" Pitfall (Accidental Globals)

In non-strict mode, assigning a value to an undeclared identifier automatically creates an entry on the global object:

```javascript
function calculateTotal() {
  // Missing 'let' / 'const' / 'var'
  discount = 0.15; // Accidental global!
}

calculateTotal();
console.log(window.discount); // 0.15 (Pollutes global namespace)

```

> **Prevention:** Always use `"use strict";` or ES Modules. In strict mode, assigning to an undeclared variable throws a `ReferenceError`.

---

### Why Global Scope Pollution is an Anti-Pattern

- **Name Collisions:** Two third-party scripts or libraries declaring `var config = {}` will overwrite each other.
- **Memory Leaks:** Variables in the global scope persist for the entire lifetime of the webpage or Node.js process and are never garbage-collected.
- **Harder to Test & Debug:** Global state creates hidden dependencies and race conditions across components.

**Best Practice:** Wrap code in ES Modules, IIFEs (Immediately Invoked Function Expressions), or scoped functions rather than declaring variables globally.

### **2. Function Scope**

- Variables declared with `var` inside a function are function-scoped.
- They are accessible only within the function where they are declared.
- This scope is created each time the function is invoked.

```javascript
function myFunction() {
  var functionScoped = "I am function scoped";
  console.log(functionScoped); // Accessible here
}

// console.log(functionScoped); // Error: not accessible outside the function
```

---

### **3. Block Scope**

- Variables declared with `let` and `const` are block-scoped.
- They are only accessible within the block `{}` in which they are defined.
- A block can be created using `if`, `for`, `while`, or any `{}` pair.

```javascript
if (true) {
  let blockScoped = "I am block scoped";
  const anotherBlockScoped = "Me too!";
  console.log(blockScoped); // Accessible here
}
// console.log(blockScoped); // Error: not accessible outside the block
```

---

### **4. Module Scope**

- Variables declared in a module are scoped to that module and are not accessible globally.
- This is used in ES6 modules where each module has its own scope.
- Use `export` and `import` to share variables/functions across modules.

**Module 1:**

```javascript
export const moduleScoped = "I am in Module 1";
```

**Module 2:**

```javascript
import { moduleScoped } from "./module1.js";
console.log(moduleScoped); // Accessible here
```

---

### **5. Lexical Scope (Static Scope)**

- Lexical scope refers to how variable accessibility is determined by the structure of the code at **write-time**, not runtime.
- A function has access to variables in its own scope, as well as in its parent scopes (closure).

```javascript
function outer() {
  let outerVar = "I am outer";

  function inner() {
    console.log(outerVar); // Accessible due to lexical scope
  }

  inner();
}

outer();
```

---

### **Summary Table**

| **Scope**      | **Description**                            | **Declared Using**     |
| -------------- | ------------------------------------------ | ---------------------- |
| Global Scope   | Accessible everywhere in the code          | `var`, `let`, `const`  |
| Function Scope | Accessible only within the function        | `var`                  |
| Block Scope    | Accessible only within the block `{}`      | `let`, `const`         |
| Module Scope   | Accessible only within the module          | `export`, `import`     |
| Lexical Scope  | Accessibility determined by code structure | Function/Closure rules |

Understanding these scopes is essential to write clean, efficient, and bug-free JavaScript code.
