***  2.1.1 var Ignores Block Scope.md ***

Variables declared with `var` are **function-scoped** (or globally scoped), meaning they completely ignore block statements such as `if`, `else`, `for`, `while`, and standalone `{ ... }` blocks.

Unlike `let` and `const` (which are block-scoped), a `var` declared inside any block "leaks" out into its enclosing function or global execution context.

---

### Core Comparison Matrix

| Feature                       | `var`                                     | `let` / `const`                             |
| ----------------------------- | ----------------------------------------- | ------------------------------------------- |
| **Scope Boundary**            | **Function / Global** only                | **Block (`{ ... }`)**, Function, & Global   |
| **Ignored Blocks**            | `if`, `switch`, `for`, `while`, bare `{}` | None (respects all `{ ... }` blocks)        |
| **Hoisting Destination**      | Top of the enclosing **function/global**  | Top of the enclosing **block** (in TDZ)     |
| **Window / Global Pollution** | Yes (attaches to `window`/`globalThis`)   | No (kept in declarative environment record) |

---

### 1. The Classic Loop Trap (`for` loop)

Because `var` ignores the block scope of a loop, every iteration overwrites the **same single variable** in memory.

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log('var i:', i);
  }, 100);
}
// Logs: 3, 3, 3 (The single shared `i` finished at 3 before timers ran)

for (let j = 0; j < 3; j++) {
  setTimeout(() => {
    console.log('let j:', j);
  }, 100);
}
// Logs: 0, 1, 2 (A new, distinct `j` binding is created for each iteration)

```

---

### 2. Accidental Overwrites in Conditional Blocks

```javascript
var role = "guest";

if (true) {
  var role = "admin"; // Overwrites the outer variable!
  console.log("Inside block:", role); // "admin"
}

console.log("Outside block:", role); // "admin" (Leaked out!)

```

With `let` or `const`, the inner `role` would create a **shadowed binding** confined strictly to the `if` block, leaving the outer `"guest"` untouched.

---

### 3. How the Engine Hoists `var` Past Blocks

During the compilation phase, the JavaScript engine hoists `var` to the top of the **enclosing function**, ignoring any intervening `{}` braces:

```javascript
// What you write:
function processData() {
  if (false) {
    var secret = 42;
  }
  console.log(secret); // undefined (NOT ReferenceError!)
}

// How the engine interprets it:
function processData() {
  var secret; // Hoisted to the top of the function
  if (false) {
    secret = 42;
  }
  console.log(secret); // undefined
}

```

---

### Only Functions Can Contain `var`

The **only** boundary `var` respects is a function body:

```javascript
function scopedFunction() {
  var hidden = "I am safe here";
}

scopedFunction();
// console.log(hidden); // ❌ ReferenceError: hidden is not defined

```
