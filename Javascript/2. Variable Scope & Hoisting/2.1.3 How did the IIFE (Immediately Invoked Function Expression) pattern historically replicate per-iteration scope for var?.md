*** copy 2.1.3 How did the IIFE (Immediately Invoked Function Expression) pattern historically replicate per-iteration scope for var?.md ***

Before block-scoped `let` was introduced in ES6, developers used **Immediately Invoked Function Expressions (IIFEs)** to manually construct a new lexical scope for each loop iteration.

Because `var` only respects **function scope**, wrapping the loop body inside an immediately invoked function forced the engine to allocate a distinct stack frame (and closure environment) for each iteration.

---

### The Problem in ES5 (Shared Scope)

With `var`, every callback shares the exact same variable `i` in the parent function/global scope:

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i); // All closures point to the same outer `i`
  }, 100);
}
// Logs: 3, 3, 3

```

---

### The IIFE Solution (Per-Iteration Scope)

By wrapping the asynchronous callback in an IIFE and passing `i` as an argument, JavaScript **binds the argument by value** to the function parameter `j`.

```javascript
for (var i = 0; i < 3; i++) {
  (function(j) {
    // `j` is a brand-new local variable inside this function's scope
    setTimeout(function() {
      console.log(j);
    }, 100);
  })(i); // Pass the current value of `i` (0, then 1, then 2)
}
// Logs: 0, 1, 2

```

---

### How It Works in Memory

Each iteration invokes the outer IIFE immediately, producing an isolated lexical environment record that gets captured by the inner timer callback:

```
[ Global / Outer Scope: var i = 3 ]
       │
       ├─► IIFE Scope 0: [ j = 0 ] ◄── Captured by Closure 0 (logs 0)
       │
       ├─► IIFE Scope 1: [ j = 1 ] ◄── Captured by Closure 1 (logs 1)
       │
       └─► IIFE Scope 2: [ j = 2 ] ◄── Captured by Closure 2 (logs 2)

```

1. **Iteration 0 (`i = 0`):** The IIFE runs with `0`. The parameter `j` is created and initialized to `0`. The `setTimeout` closure captures this specific activation record.
2. **Iteration 1 (`i = 1`):** The IIFE runs with `1`. A **new function execution context** is pushed onto the call stack with its own independent `j = 1`.
3. **Iteration 2 (`i = 2`):** Another independent context is created with `j = 2`.

When the timers finally fire after 100ms, each closure inspects its own preserved lexical environment and reads its respective `j` value.

---

### Alternative ES5 Variations

Developers also used two related patterns to achieve the same result:

#### 1. Function Factory / Currying

```javascript
function makeHandler(capturedIndex) {
  return function() {
    console.log(capturedIndex);
  };
}

for (var i = 0; i < 3; i++) {
  setTimeout(makeHandler(i), 100);
}

```

#### 2. Passing Arguments to `setTimeout`

```javascript
for (var i = 0; i < 3; i++) {
  // `setTimeout` passes additional arguments directly to the callback function
  setTimeout(function(capturedIndex) {
    console.log(capturedIndex);
  }, 100, i);
}

```

---

### Comparison: ES5 IIFE vs. ES6 `let`

| Feature               | ES5 (IIFE + `var`)                                    | ES6 (`let`)                                      |
| --------------------- | ----------------------------------------------------- | ------------------------------------------------ |
| **Mechanism**         | Creates a new function call stack frame per iteration | Spec invokes `CreatePerIterationEnvironment`     |
| **Syntax Overhead**   | Verbose wrapper function boilerplate                  | Built into `for (let i = 0; ...)` syntax         |
| **Engine Allocation** | Full function object execution context                | Declarative environment record (optimized by V8) |
