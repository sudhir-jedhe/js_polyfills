*** copy 2.8.3 How JavaScript Execution Contexts and Lexical Environments work.md ***

Every piece of JavaScript code runs inside an **Execution Context**, and every context relies on a **Lexical Environment** to track identifiers and resolve variables.

Understanding these two components reveals how JavaScript handles hoisting, scope chains, closures, and the call stack under the hood.

---

### 1. The Execution Context (The Container)

An **Execution Context (EC)** is an internal specification wrapper created by the engine whenever code is evaluated.

```
┌─────────────────────────────────────────────────────────────┐
│                      Execution Context                      │
│                                                             │
│  1. LexicalEnvironment     ──► Resolves `let`, `const`, etc.│
│  2. VariableEnvironment    ──► Resolves `var`, declarations │
│  3. ThisBinding            ──► Value of `this`              │
└─────────────────────────────────────────────────────────────┘

```

#### Types of Execution Contexts

* **Global Execution Context (GEC):** Created when the script first starts. There is only one GEC per environment.
* **Function Execution Context (FEC):** Created dynamically each time a function is **invoked** (not defined).
* **`eval()` Execution Context:** Created inside code executed with `eval()`.

#### The Call Stack

Execution Contexts are pushed and popped from the **Call Stack** (LIFO: Last In, First Out). The context at the top of the stack is the currently executing thread.

---

### 2. The Two Phases of an Execution Context

Whenever an Execution Context is spawned, it executes in two distinct phases:

```
[ Phase 1: Creation Phase ] 
  ├── Scans for declarations
  ├── Sets up memory allocation (Hoisting)
  │     ├── `var` ──► initialized to `undefined`
  │     ├── `let`/`const` ──► uninitialized (TDZ)
  │     └── `function` ──► stored in memory with body
  └── Initializes `this` binding & Lexical Environment

[ Phase 2: Execution Phase ]
  └── Interprets & executes code line-by-line (assigns values, executes calls)

```

---

### 3. The Anatomy of a Lexical Environment

A **Lexical Environment** is a concrete engine structure used to resolve identifier names to their values. It consists of two parts:

$$\text{Lexical Environment} = \text{Environment Record} + \text{Outer Environment Reference}$$

```
┌───────────────────────────────────────────────────────────────────────────┐
│                            Lexical Environment                            │
│                                                                           │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ 1. Environment Record                                               │  │
│  │    Stores local variables, functions, and parameters.               │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────────────────┐  │
│  │ 2. Outer Reference (outerEnv)                                       │  │
│  │    A physical pointer to the parent Lexical Environment (Lexical).  │  │
│  └─────────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────────┘

```

#### A. Environment Records (The Storage)

* **Declarative Environment Record:** Used by function and block scopes to store `let`, `const`, `class`, and function declarations directly in memory slots.
* **Object Environment Record:** Used in the global context to bind bindings to a concrete object (e.g., `window`).
* **Global Environment Record:** A hybrid record containing both an *Object Record* (for `var`) and a *Declarative Record* (for `let`/`const`).

#### B. Outer Environment Reference (The Scope Chain Link)

The **Outer Reference** points directly to the lexical environment where the current code was **physically written in the source file**, regardless of where it is called at runtime.

---

### 4. How Variable Resolution Works (The Scope Chain)

When code requests an identifier (e.g., `console.log(x)`):

1. The engine checks the current context's **Environment Record**.
2. If found, it reads the value.
3. If not found, it traverses the **Outer Reference** to inspect the parent's Environment Record.
4. It repeats this traversal up to the **Global Lexical Environment**.
5. If still not found, it throws a `ReferenceError: x is not defined`.

```javascript
const globalVar = 'Global';

function outer() {
  const outerVar = 'Outer';

  function inner() {
    const innerVar = 'Inner';
    console.log(innerVar);  // 1. Found in current Lexical Environment
    console.log(outerVar);  // 2. Traverses outer reference -> found in outer's Lexical Environment
    console.log(globalVar); // 3. Traverses outer reference -> found in Global Environment
  }

  inner();
}

outer();

```

---

### 5. Why Closures Exist (Persistent Lexical Environments)

When an execution context finishes executing, it is popped off the Call Stack. Normally, its memory would be garbage collected.

However, if an inner function retains a reference to that lexical environment via its internal `[[Scopes]]` slot, **the engine retains the Lexical Environment on the Heap**:

```javascript
function makeCounter() {
  let count = 0; // Lives in makeCounter's Lexical Environment

  return function increment() {
    count++;
    return count;
  };
}

const counter = makeCounter();
// `makeCounter()` Execution Context is popped off the Call Stack.
// BUT its Lexical Environment remains alive on the Heap!

console.log(counter()); // 1
console.log(counter()); // 2

```

### Summary Checklist

| Concept                | What It Is                                   | Primary Job                                                                  |
| ---------------------- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| **Execution Context**  | The active execution frame on the Call Stack | Coordinates execution phases, `this`, and environment records.               |
| **Environment Record** | Key-value storage dictionary                 | Holds variables, arguments, and function declarations.                       |
| **Outer Reference**    | Pointer to the enclosing lexical scope       | Powers scope chain resolution and enables closures.                          |
| **Lexical Scoping**    | Static scoping rules                         | Ensures functions resolve variables where they were **defined**, not called. |
