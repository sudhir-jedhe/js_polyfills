***  2.3. Const.md ***

Here is a clean, structured recreation of the documentation for the JavaScript `const` declaration, with all ad copy and UI clutter removed.

## The `const` Declaration

The `const` declaration creates block-scoped local variables. The value of a constant cannot be changed through reassignment, and it cannot be redeclared. However, if a constant holds an object or array, its properties or elements can still be modified or mutated.

### Syntax

```javascript
const name1 = value1;
const name1 = value1, name2 = value2;
const name1 = value1, name2 = value2, /* …, */ nameN = valueN;

```

* **`nameN`**: The name of the variable to declare. Must be a legal JavaScript identifier or a destructuring binding pattern.
* **`valueN`**: The initial value assigned to the variable. Must be a legal expression.

---

## 1. Description and Rules

The `const` declaration behaves almost identically to `let`, with two critical differences:

1. **Initializers Are Required:** You must assign a value immediately upon declaration.
2. **Immutable Bindings:** You cannot reassign the variable identifier to a new value.

```javascript
// Missing initializer throws a SyntaxError
const FOO; // SyntaxError: Missing initializer in const declaration

```

### Core Characteristics

* **Block Scoped:** Constrained to the nearest block, function, or static initialization block.
* **Temporal Dead Zone (TDZ):** Accessing a `const` variable before its declaration line throws a `ReferenceError`.
* **No Global Object Properties:** Declaring `const` at the top level of a script does not create properties on `globalThis` or `window`.
* **No Redeclarations:** Cannot be redeclared within the same scope by `let`, `var`, `function`, or another `const`.

---

## 2. Immutable Binding vs. Immutable Values

A common misconception is that `const` makes the *value* immutable. In reality, `const` creates an **immutable binding** (the variable reference cannot change), but the underlying value itself can still be mutated if it is an object or array.

Think of `const` as meaning **"a variable whose identity remains constant"**, not "whose contents remain constant."

### Objects

Assigning a new object to a `const` variable throws an error, but updating its properties works without issue:

```javascript
const MY_OBJECT = { key: "value" };

// Reassignment fails:
MY_OBJECT = { OTHER_KEY: "value" }; // TypeError: Assignment to constant variable.

// Property mutation works:
MY_OBJECT.key = "otherValue"; 
console.log(MY_OBJECT.key); // "otherValue"

```

> **Note:** To make an object's properties truly immutable, use `Object.freeze()`.

### Arrays

Similarly, assigning a new array fails, but mutating the array using methods like `.push()`, `.pop()`, or index assignment is permitted:

```javascript
const MY_ARRAY = [];

// Reassignment fails:
MY_ARRAY = ["B"]; // TypeError: Assignment to constant variable.

// Array mutation works:
MY_ARRAY.push("A"); 
console.log(MY_ARRAY); // ["A"]

```

---

## 3. Scope and Shadowing Examples

Because `const` is block-scoped, declaring a `const` variable with the same name inside an inner block creates a new, separate binding without affecting the outer scope.

```javascript
const MY_FAV = 7;

if (MY_FAV === 7) {
  // Fine: creates a new block-scoped variable
  const MY_FAV = 20;
  console.log(MY_FAV); // 20

  // SyntaxError: var ignores block scope and attempts to redeclare the outer const
  // var MY_FAV = 20; 
}

console.log(MY_FAV); // 7

```

---

## 4. Declaration with Destructuring

You can use `const` with destructuring patterns to unpack values from arrays or objects into constant bindings:

```javascript
const result = /(a+)(b+)(c+)/.exec("aaabcc");
const [, a, b, c] = result;

console.log(a, b, c); // "aaa" "b" "cc"

```

`const` creates an **immutable binding**, not an **immutable value**.

The difference comes down to how JavaScript manages memory for primitives versus reference types:

* **Primitives (numbers, strings, booleans):** The variable holds the actual value directly in memory. Reassigning changes the stored value, which `const` blocks.
* **Objects and Arrays (Reference Types):** The variable holds a **memory address (pointer)** pointing to where the object lives in heap memory—not the actual data itself.

---

**What `const` Protects vs. Allows**

* **Reassignment (Forbidden):** Pointing the variable to a different memory address throws a `TypeError`.

```javascript
const user = { name: "Alice" };
user = { name: "Bob" }; // TypeError: Assignment to constant variable.

```

* **Mutation (Allowed):** Modifying the data inside the object does not alter the variable's memory address pointer.

```javascript
const user = { name: "Alice" };
user.name = "Bob";      // Allowed: The pointer remains unchanged.
user.age = 30;          // Allowed: Adding properties modifies the heap object.

```

---

**How to Achieve True Immutability**

To make an object's contents read-only, use `Object.freeze()`:

```javascript
const config = Object.freeze({
  endpoint: "https://api.example.com",
  timeout: 5000
});

config.timeout = 10000; // Fails silently in non-strict mode, throws TypeError in strict mode

```

*(Note: `Object.freeze()` is shallow. Nested objects must be frozen individually or via a recursive deep freeze function.)*
