### Step-by-Step Breakdown

**Core Rule (`catch` Parameter Scoping & `var` Shadowing):**

* A `catch (param)` clause creates a **new block-scoped lexical environment** for its parameter.
* While `var` declarations inside a `catch` block hoist to the enclosing function/global scope, **identifier resolution at runtime resolves to the closest lexical scope first**.
* If a `var` declaration inside `catch (x)` shares the exact same name `x`, the assignment `x = ...` modifies the **catch parameter**, leaving the outer variable untouched.

---

1. **`catch { var a = 'a1' }` (Optional Catch Binding):**

* There is no catch parameter binding.
* `var a = 'a1'` assigns directly to the outer variable `a`.
* `console.log(a)` logs **`"a1"`**.

1. **`catch (b) { var b = 'b1' }` (Catch Parameter Shadowing):**

* The parameter `b` receives the thrown `Error` object and shadows the outer `b` within the block.
* Executing `b = 'b1'` resolves to the local catch parameter `b` and overwrites it.
* The outer variable `b` remains untouched with its original value `'b'`.
* `console.log(b)` logs **`"b"`**.

1. **`catch (error) { var c = 'c1' }`:**

* The catch parameter is named `error`, so it does not shadow `c`.
* `c = 'c1'` resolves to the outer variable `c` and updates it.
* `console.log(c)` logs **`"c1"`**.
