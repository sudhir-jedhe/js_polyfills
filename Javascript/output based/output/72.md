```js
// This is a JavaScript Quiz from BFE.dev

class MyArray extends Array {
  get length() {
    return 3
  }
}

const arr1 = new MyArray(10)
console.log(arr1.length)

const arr2 = new Array(10)
console.log(arr2.length)
```

**Output:**

```javascript
10
10

```

### Step-by-Step Breakdown

**Core Rule (Own Properties vs. Prototype Accessors on Array Exotic Objects):**

* Arrays in JavaScript are **Array Exotic Objects**, which always possess an **own property** named `length` (`{ writable: true, enumerable: false, configurable: false, value: ... }`).
* When performing a property lookup (`arr1.length`), JavaScript checks the object's **own properties first** before traversing up the prototype chain.

---

1. **`new MyArray(10)`:**

* Invoking `new MyArray(10)` calls the default derived constructor `super(10)`, which creates an Array exotic instance with an own property `length` initialized to `10`.
* The getter `get length()` resides on `MyArray.prototype`.
* Because `length` exists directly as an own property on `arr1`, property lookup finds `10` immediately without checking `MyArray.prototype`.
* `console.log(arr1.length)` outputs **`10`**.

1. **`new Array(10)`:**

* Standard array initialization with length 10.
* `console.log(arr2.length)` outputs **`10`**.
