```js
// This is a JavaScript Quiz from BFE.dev

let val = 0

class A {
  set foo(_val) {
    val = _val
  }
  get foo() {
    return val
  }
}

class B extends A { }

class C extends A {
  get foo() {
    return val
  }
}

const b = new B()
console.log(b.foo)
b.foo = 1
console.log(b.foo)

const c = new C()
console.log(c.foo)
c.foo = 2
console.log(c.foo)
console.log(b.foo)
```

**Output:**

*(Assuming non-strict mode)*

```javascript
0
1
1
1
1

```

*(In strict mode `'use strict'`, `c.foo = 2` throws `TypeError: Cannot set property foo of #<C> which has only a getter`)*

---

### Step-by-Step Breakdown

**Core Rule (Accessor Overriding in Class Inheritance):**

* When a subclass defines a getter (`get foo()`) without defining a corresponding setter (`set foo()`), the property descriptor on the subclass prototype (`C.prototype`) has `{ get: [Function], set: undefined }`.
* This completely shadows both the getter **and** the setter from the parent class prototype (`A.prototype`).
* Attempting to assign `c.foo = 2` finds the accessor on `C.prototype` with no setter (`set: undefined`), so the assignment fails silently in non-strict mode without modifying `val`.

---

1. **`const b = new B()`:**

* `B` inherits both getter and setter from `A.prototype`.
* `console.log(b.foo)` $\rightarrow$ calls `A.prototype` getter $\rightarrow$ logs **`0`**.
* `b.foo = 1` $\rightarrow$ calls `A.prototype` setter $\rightarrow$ `val` becomes `1`.
* `console.log(b.foo)` $\rightarrow$ calls `A.prototype` getter $\rightarrow$ logs **`1`**.

1. **`const c = new C()`:**

* `C.prototype` defines only `get foo()`, leaving `set` as `undefined`.
* `console.log(c.foo)` $\rightarrow$ calls `C.prototype` getter $\rightarrow$ logs **`1`**.
* `c.foo = 2` $\rightarrow$ finds no setter on `C.prototype`, so the assignment is ignored and `val` remains `1`.
* `console.log(c.foo)` $\rightarrow$ logs **`1`**.
* `console.log(b.foo)` $\rightarrow$ logs **`1`**.
