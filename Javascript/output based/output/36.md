```js
// This is a JavaScript Quiz from BFE.dev

Promise.resolve(1)
.finally((data) => {
  console.log(data)
  return Promise.reject('error')
})
.catch((error) => {
  console.log(error)
  throw 'error2'
})
.finally((data) => {
  console.log(data)
  return Promise.resolve(2).then(console.log)
})
.then(console.log)
.catch(console.log)

```

**Output:**

```javascript
undefined
"error"
undefined
2
"error2"

```

### Step-by-Step Breakdown

**Core Rules for `Promise.prototype.finally(callback)`:**

* The callback passed to `.finally()` receives **no arguments** (`data` is always `undefined`).
* If the callback returns a promise that **rejects** (or throws an error), the returned promise becomes rejected with that new reason.
* If the callback returns a promise that **fulfills** (e.g. `Promise.resolve(2)`), the resolved value is **ignored**, and the original state and value/rejection from earlier in the chain are preserved and passed forward.

---

1. **`Promise.resolve(1).finally(...)`**

* The `.finally()` callback receives no parameters $\rightarrow$ `data` is `undefined`.
* `console.log(data)` logs: **`undefined`**.
* It returns `Promise.reject('error')`, overriding the chain state with a rejected promise with reason `'error'`.

1. **`.catch((error) => ...)`**

* Catches the rejection reason `'error'`.
* `console.log(error)` logs: **`"error"`**.
* Executes `throw 'error2'`, returning a rejected promise with reason `'error2'`.

1. **Second `.finally(...)**`

* Receives no parameters $\rightarrow$ `data` is `undefined`.
* `console.log(data)` logs: **`undefined`**.
* Evaluates `Promise.resolve(2).then(console.log)`:
* Enqueues a microtask that logs: **`2`**.

* Because this inner promise fulfills, its value is ignored, and the incoming rejection (`'error2'`) is passed down the chain.

1. **`.then(...)` and `.catch(...)**`

* The `.then(console.log)` handler is skipped because the promise is in a rejected state.
* The final `.catch(console.log)` catches and logs the active rejection: **`"error2"`**.
