### Step-by-Step Breakdown

**Core Hoisting Rules:**

1. **Functions hoist before `var`:** Function declarations take priority and are hoisted with their definitions.
2. **Duplicate `var` declarations are ignored:** A `var` declaration with the same name as an existing function declaration will not overwrite the function *at hoist time*, but runtime assignments (`=`) will.
3. **Named Function Expressions (NFEs):** The inner function name in `const f = function e() {}` is only accessible inside the function itself, not in the outer scope.

---

1. **Section `a` $\rightarrow$ `"number"**`

* Hoisting order: `function a() {}` is hoisted first. The `var a` declaration is redundant and ignored during creation.
* Execution phase: `a = 1` reassigns `a` from the function to the number `1`.
* `typeof a` logs `"number"`.

1. **Section `b` $\rightarrow$ `"number"**`

* `function b() {}` is hoisted first.
* Execution phase: `b = 1` assigns the number `1` to `b`.
* `typeof b` logs `"number"`.

1. **Section `c` $\rightarrow$ `"number"**`

* `function c() {}` is hoisted first.
* Execution phase: `c = 1` assigns the number `1` to `c`.
* `typeof c` logs `"number"`.

1. **Section `d` (IIFE & Outer Scope):**

* **Inside the IIFE:**
* `function d() {}` is hoisted to the top of the IIFE's local function scope.
* `d = '2'` reassigns the **local** `d` to the string `'2'`.
* `typeof d` inside the IIFE logs **`"string"`**.

* **Outside the IIFE:**
* The global `d` was never touched by the IIFE, remaining `1`.
* `typeof d` logs **`"number"`**.

1. **Section `e` $\rightarrow$ `"number"**`

* `const f = function e() {}` creates a Named Function Expression.
* The identifier `e` is only bound inside the body of `f`.
* In the outer scope, `e` refers solely to `var e = 1`.
* `typeof e` logs **`"number"`**.
