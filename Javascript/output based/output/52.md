# File 52

```js
// This is a JavaScript Quiz from BFE.dev

console.log(1)

setTimeout(() => {
  console.log(2)
}, 100)

requestAnimationFrame(() => {
  console.log(3)
})

requestAnimationFrame(() => {
  console.log(4)
  setTimeout(() => {
    console.log(5)
  }, 10)
})

const end = Date.now() + 200;
while (Date.now() < end) {
}

console.log(6)
```

**Output:**

```javascript
1
6
3
4
2
5

```

---

### Step-by-Step Breakdown

**Core Event Loop Lifecycle:**

1. **Script Task & Synchronous Execution:**

* `console.log(1)` runs $\rightarrow$ logs **`1`**.
* `setTimeout(..., 100)` registers a timer callback to be placed on the Task Queue after 100ms.
* Two `requestAnimationFrame` (rAF) callbacks are registered for the next frame rendering pipeline.
* The synchronous `while` loop blocks the main thread for 200ms.
* During this 200ms block, the 100ms timer expires and its macrotask is queued into the Timer Task Queue.

* `console.log(6)` runs $\rightarrow$ logs **`6`**.
* The initial script (the currently running Task) finishes.

1. **Rendering Phase (`requestAnimationFrame`):**

* At the end of the task, the browser checks for a rendering opportunity. Because the main thread was blocked for 200ms (far exceeding the ~16.6ms frame budget), an "Update the rendering" step occurs immediately before picking the next task.
* **First rAF:** Executes `console.log(3)` $\rightarrow$ logs **`3`**.
* **Second rAF:** Executes `console.log(4)` $\rightarrow$ logs **`4`**, and schedules `setTimeout(..., 10)`.

1. **Task Queue (Macrotasks):**

* The event loop picks the oldest task from the task queue: the 100ms timer callback (which has already elapsed). It executes $\rightarrow$ logs **`2`**.
* After its 10ms delay expires, the nested timer task executes $\rightarrow$ logs **`5`**.
