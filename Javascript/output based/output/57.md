# File 57

```js
const a = {}
Object.defineProperty(a, 'foo1', {
  value: 1
})
const b = Object.create(a)
b.foo2 = 1

console.log(b.foo1)
console.log(b.foo2)

b.foo1 = 2
b.foo2 = 2


console.log(b.foo1)
console.log(b.foo2)

```

**Output:**

*(Assuming non-strict mode)*

```javascript
1
1
1
2

```

*(In strict mode `'use strict'`, `b.foo1 = 2` throws `TypeError: Cannot assign to read only property 'foo1' of object '#<Object>'`)*

---

### Step-by-Step Breakdown

**Core Rule (Prototype Property Assignment vs. Shadowing):**

* When using `Object.defineProperty()`, descriptor flags default to `false`. Therefore, `foo1` on `a` has `{ writable: false, configurable: false, enumerable: false }`.
* When assigning to a property on an object (`b.foo1 = 2`), JavaScript looks up the prototype chain:
* If a non-writable data property (`writable: false`) exists on the **prototype object**, JavaScript prevents creating a shadowing property on the derived object `b`. The assignment silently fails in non-strict mode (or throws a `TypeError` in strict mode).
* If the property is defined normally on `b` (`b.foo2 = 1`), it is a writable own-property, so `b.foo2 = 2` successfully updates it.

---

1. **Initial Reads:**

* `console.log(b.foo1)` $\rightarrow$ reads `1` inherited from prototype `a`.
* `console.log(b.foo2)` $\rightarrow$ reads `1` from `b`'s own property.

1. **Assignments:**

* `b.foo1 = 2` $\rightarrow$ prototype `a.foo1` is non-writable (`writable: false`), so the assignment fails and `b.foo1` is not set on `b`.
* `b.foo2 = 2` $\rightarrow$ `foo2` is writable on `b`, so its value updates to `2`.

1. **Subsequent Reads:**

* `console.log(b.foo1)` $\rightarrow$ still evaluates to **`1`** (from prototype `a`).
* `console.log(b.foo2)` $\rightarrow$ evaluates to **`2`**.
