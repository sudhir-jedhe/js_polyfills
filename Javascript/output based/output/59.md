```js
// This is a JavaScript Quiz from BFE.dev

class A {
  val = 1
  get foo() {
    return this.val
  }
}

class B {
  val = 2
  set foo(val) {
    this.val = val
  }
}
const a = new A()
const b = new B()
console.log(a.foo)
console.log(b.foo)
b.foo = 3
console.log(b.val)
console.log(b.foo)
```

**Output:**

```javascript
1
undefined
3
undefined

```

### Step-by-Step Breakdown

**Core Rule (Accessor Properties):**

* When a class defines only a getter (`get foo()`), reading the property invokes the function, while writing to it is ignored (or throws in strict mode).
* When a class defines only a setter (`set foo()`), the property descriptor on the prototype has `{ get: undefined, set: [Function] }`. Attempting to **read** the property returns **`undefined`** because no getter exists.

---

1. **`console.log(a.foo)` $\rightarrow$ `1**`

* Class `A` defines a getter `foo()`.
* Calling the getter returns `a.val`, which is **`1`**.

1. **`console.log(b.foo)` $\rightarrow$ `undefined**`

* Class `B` defines only a setter `set foo(val)` and no getter.
* Reading `b.foo` evaluates to **`undefined`**.

1. **`b.foo = 3` and `console.log(b.val)` $\rightarrow$ `3**`

* Invokes the setter `set foo(3)` on `B.prototype`, executing `this.val = 3`.
* `b.val` is updated to `3`, so logging `b.val` outputs **`3`**.

1. **`console.log(b.foo)` $\rightarrow$ `undefined**`

* Reading `b.foo` still looks up the getter on `B.prototype`, which remains `undefined`.
