**Why each evaluates this way:**

* **`0 == false` $\rightarrow$ `true**`: When comparing a number and a boolean, the boolean is coerced to a number (`Number(false)` is `0`), resulting in `0 == 0`.
* **`'' == false` $\rightarrow$ `true**`: Both sides are converted to numbers (`Number('')` is `0`, `Number(false)` is `0`), resulting in `0 == 0`.
* **`[] == false` $\rightarrow$ `true**`: The array is converted to a primitive via `[].toString()` (which is `""`), and `"" == false` coerces to `0 == 0`.
* **`undefined == false` $\rightarrow$ `false**`: `undefined` only loosely equals `null` or itself. It does not coerce to numeric `0` for equality with booleans.
* **`null == false` $\rightarrow$ `false**`: Like `undefined`, `null` only loosely equals `undefined` or itself.
* **`'1' == true` $\rightarrow$ `true**`: Both convert to numbers (`Number('1')` is `1`, `Number(true)` is `1`), resulting in `1 == 1`.
* **`1n == true` $\rightarrow$ `true**`: `true` coerces to `1`. Comparing BigInt `1n` and Number `1` checks mathematical numeric equality, so `1 == 1`.
* **`' 1     ' == true` $\rightarrow$ `true**`: `Number(' 1     ')` strips whitespace and parses to `1`, which equals `Number(true)`.
