```js
// This is a JavaScript Quiz from BFE.dev 

let num

for (let i = 0; i < 5; i++) {
  num = i
  setTimeout(() => {
    console.log(num)
  }, 100)
}
```

**Output:**

```javascript
4
4
4
4
4

```

---

### Step-by-Step Breakdown

**Core Rule (Variable Scope vs. Closures with Asynchronous Timers):**

* `let i` is scoped to each individual iteration of the `for` loop, but the variable **`num`** is declared outside the loop in the parent scope.
* Each iteration updates the single, shared `num` reference: `num = i`.
* The `setTimeout` callbacks form a closure over the outer `num` variable, not `i`.

---

1. **Synchronous Loop Execution:**

* **`i = 0`** $\rightarrow$ `num = 0`, schedules Timer 1 (100ms).
* **`i = 1`** $\rightarrow$ `num = 1`, schedules Timer 2 (100ms).
* **`i = 2`** $\rightarrow$ `num = 2`, schedules Timer 3 (100ms).
* **`i = 3`** $\rightarrow$ `num = 3`, schedules Timer 4 (100ms).
* **`i = 4`** $\rightarrow$ `num = 4`, schedules Timer 5 (100ms).
* The loop finishes, leaving `num` at **`4`**.

1. **Asynchronous Timer Execution (After 100ms):**

* All 5 callbacks run from the Macrotask Queue.
* When each callback executes `console.log(num)`, it reads the current value of the shared outer variable `num`, which is **`4`**.
* Logs **`4`** five times in sequence.
