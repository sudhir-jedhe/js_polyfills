```js
let a = 1;

  let foo = () => a
  let a = 2;
  console.log(foo())
}())
```

**Output:**

---

### Step-by-Step Breakdown

**Core Rules (Lexical Scope & Temporal Dead Zone):**

* **Lexical Scoping / Shadowing:** The inner `let a` shadows the outer `let a = 1` throughout the entire IIFE block.
* **TDZ (Temporal Dead Zone):** A `let` variable cannot be accessed until its declaration line is evaluated. However, simply *defining* a function that captures a TDZ variable does **not** trigger a ReferenceError—the error only occurs if the function is *invoked* before the variable is initialized.

---

1. **`let foo = () => a`:**

* The arrow function captures `a` from the current scope (the inner `a`).
* At this point, the inner `a` is in the TDZ, but `foo` is merely created, not called.

1. **`let a = 2`:**

* The inner `a` is initialized with the value `2` and exits the TDZ.

1. **`console.log(foo())`:**

* `foo()` is invoked.
* It evaluates `a` in its enclosing scope, where `a` is already initialized to `2`.
* Returns and logs **`2`**.
