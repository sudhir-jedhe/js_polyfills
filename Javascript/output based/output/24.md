### Step-by-Step Breakdown

**Core Comparison Rules:**

* **`==` (Loose Equality):** Performs type coercion before comparing values.
* **`===` (Strict Equality):** Checks both type and value without coercion. It treats `+0` and `-0` as equal, but `NaN` is not equal to anything, including itself (`NaN === NaN` is `false`).
* **`Object.is(a, b)` (SameValue Equality):** Strictly checks equality without coercion, with two key differences compared to `===`:
* `Object.is(+0, -0)` $\rightarrow$ **`false`**
* `Object.is(NaN, NaN)` $\rightarrow$ **`true`**

---

1. **`0` vs `'0'`:**

* `0 == '0'` $\rightarrow$ `'0'` coerces to number `0` $\rightarrow$ **`true`**
* `0 === '0'` $\rightarrow$ Different types (`number` vs `string`) $\rightarrow$ **`false`**
* `Object.is(0, '0')` $\rightarrow$ Different types $\rightarrow$ **`false`**

1. **`0` vs `0`:**

* All three operations verify identical primitive numbers $\rightarrow$ **`true`**, **`true`**, **`true`**

1. **`0` vs `-0`:**

* `0 == -0` $\rightarrow$ Numeric equality treats them as equal $\rightarrow$ **`true`**
* `0 === -0` $\rightarrow$ Strict equality treats them as equal $\rightarrow$ **`true`**
* `Object.is(0, -0)` $\rightarrow$ Distinguishes signed zeros $\rightarrow$ **`false`**

1. **`NaN` vs `NaN`:**

* `NaN == NaN` $\rightarrow$ By specification, `NaN` does not equal any value $\rightarrow$ **`false`**
* `NaN === NaN` $\rightarrow$ `NaN` is not strictly equal to itself $\rightarrow$ **`false`**
* `Object.is(NaN, NaN)` $\rightarrow$ Treats both as the same entity $\rightarrow$ **`true`**

1. **`0` vs `false`:**

* `0 == false` $\rightarrow$ `Number(false)` coerces to `0` $\rightarrow$ **`true`**
* `0 === false` $\rightarrow$ Different types (`number` vs `boolean`) $\rightarrow$ **`false`**
* `Object.is(0, false)` $\rightarrow$ Different types $\rightarrow$ **`false`**
