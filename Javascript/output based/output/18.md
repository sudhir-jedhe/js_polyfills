# File 18

```js
const p1 = Promise.resolve(1)
const p2 = new Promise((resolve) => resolve(p1))
const p3 = Promise.resolve(p1)
const p4 = p2.then(() => new Promise((resolve) => resolve(p3)))
const p5 = p4.then(() => p4)

console.log(p1 == p2)
console.log(p1 == p3)
console.log(p3 == p4)
console.log(p4 == p5)
```

**Output:**

```javascript
false
true
false
false

```

---

### Step-by-Step Breakdown

**1. `console.log(p1 == p2)` $\rightarrow$ `false**`

* `new Promise((resolve) => resolve(p1))` always creates a brand new, distinct Promise instance. Even though it adopts the state and value of `p1`, `p2` and `p1` reside at different references in memory.

**2. `console.log(p1 == p3)` $\rightarrow$ `true**`

* `Promise.resolve(value)` has a built-in fast path: if the passed `value` is already an actual native Promise, it simply returns the exact same Promise instance without wrapping it. Thus, `p3` is an identical reference to `p1`.

**3. `console.log(p3 == p4)` $\rightarrow$ `false**`

* Calling `.then()` on any promise (`p2.then(...)`) always constructs and returns a new Promise instance immediately. Hence, `p4` is a newly generated instance and cannot equal `p3`.

**4. `console.log(p4 == p5)` $\rightarrow$ `false**`

* Calling `.then()` on `p4` returns a new Promise instance `p5`. Even though the callback inside `.then()` returns `p4` upon resolution, the Promise object returned by the `.then()` call itself (`p5`) is created synchronously at chain definition time as a separate reference.
