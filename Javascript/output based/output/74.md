```js
// This is a JavaScript Quiz from BFE.dev 

class MyArray extends Uint8Array {
  get length() {
    return 3
  }
}

const arr1 = new MyArray(10)
console.log(arr1.length)

const arr2 = new Uint8Array(10)
console.log(arr2.length)
```

**Output:**

```javascript
3
10

```

---

### Step-by-Step Breakdown

**Core Rule (`Array` vs. `TypedArray` Exotic Objects):**

* **Standard `Array`:** Possesses an **own property** named `length` on each instance (`{ value: n, writable: true, enumerable: false, configurable: false }`).
* **`TypedArray` (e.g., `Uint8Array`):** Does **not** have an own `length` property on instances. Instead, `length` is defined as an **accessor descriptor (getter)** on `%TypedArray%.prototype` (`Uint8Array.prototype.__proto__`).

---

1. **`const arr1 = new MyArray(10)`:**

* `arr1` is an instance of `MyArray` (and `Uint8Array`).
* Because `arr1` has no own property named `length`, JavaScript walks up the prototype chain.
* The first `length` property encountered is the custom getter `get length() { return 3 }` on `MyArray.prototype`.
* The getter executes and returns **`3`**.
* `console.log(arr1.length)` outputs **`3`**.

1. **`const arr2 = new Uint8Array(10)`:**

* `arr2` does not have an own `length` property either.
* Prototype lookup traverses to the built-in getter on `%TypedArray%.prototype`.
* The built-in getter reads the internal slot `[[ArrayLength]]` of the typed array, which is `10`.
* `console.log(arr2.length)` outputs **`10`**.
