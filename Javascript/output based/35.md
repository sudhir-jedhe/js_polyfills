Here is how this classic JavaScript hoisting question executes depending on the declaration order:

### Case 1: `var magic = 1` declared *before* the function call

```javascript
var magic = 1;

function magic() {
  console.log("Hello from magic!");
}

magic();

```

**Output:**

```text
TypeError: magic is not a function

```

#### Step-by-Step Explanation

1. **Creation Phase (Hoisting):**

* Function declarations take precedence over `var` during hoisting.
* `magic` is initially created in memory as a function: `magic = function() { ... }`.
* `var magic;` is ignored during hoisting because an identifier named `magic` already exists.

1. **Execution Phase (Line by Line):**

* `magic = 1;` runs $\rightarrow$ **`magic` is reassigned to the number `1**`.
* When JavaScript reaches `magic()`, it tries to invoke `1()`, throwing a **`TypeError: magic is not a function`**.

---

### Case 2: `magic()` called *before* `var magic = 1`

```javascript
magic();

var magic = 1;

function magic() {
  console.log("Hello from magic!");
}

```

**Output:**

```text
Hello from magic!

```

#### Why?

* During hoisting, the entire `function magic() { ... }` is hoisted to the top.
* When `magic()` is invoked on line 1, it executes the function successfully before the variable assignment (`magic = 1`) takes place.
