* **The Problem:** Using multiple `&nbsp;` (non-breaking spaces) for layout, margins, or indentation creates rigid, non-responsive HTML that breaks screen-reader readability.
* **CSS Solutions:**
* Use **`margin`** / **`padding`** or CSS Grid/Flexbox `gap`.
* Use CSS property **`white-space: pre-wrap;`** to preserve natural spaces.
* Use **`word-spacing`** or **`text-indent`**.

### 5. `this` Boxing in Non-Strict Function Calls (`10.52.50 PM.png`)

```javascript
function test() {
  console.log(typeof this);
}

test.call("");

```

* **Explanation:** In standard non-strict (sloppy) mode, passing a primitive string `""` to `.call()` or `.apply()` automatically **boxes** the primitive into its object wrapper (`new String("")`).
* Inside `test`, `this` is a `String` wrapper object.
* **Output:** `"object"` *(In strict mode `"use strict"`, it retains its primitive type and returns `"string"`)*.

### 6. Class Hoisting & Temporal Dead Zone (TDZ) (`10.50.08 PM.png`)

```javascript
console.log(Person);
class Person {}

```

* **Explanation:** Unlike function declarations (which are fully hoisted and initialized), ES6 `class` declarations are hoisted without initialization and remain in the **Temporal Dead Zone (TDZ)** until execution reaches line 4.
* Attempting to access a class before its declaration line throws an error.
* **Output:** `ReferenceError: Cannot access 'Person' before initialization`

```javascript
const x = (1, 2, 3, 4);

console.log('x=', x);

```

* **Concept:** Inside the parentheses `(1, 2, 3, 4)`, the **comma operator** evaluates each expression from left to right and returns the value of the final operand (`4`).
* **Step-by-step:**

1. `1` is evaluated.
2. `2` is evaluated.
3. `3` is evaluated.
4. `4` is evaluated and returned as the result to initialize `x`.

* **Output:**

```text
x= 4

```
