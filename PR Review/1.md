Here is a structured overview of the concepts illustrated in the **PR Review Blind Spot** guide:

---

### Core Philosophy

* **Key Idea:** PR review checks the code; E2E (End-to-End) checks the product in the browser.
* **Core Rule:** *"Review the code. Then verify the **promise** the code makes."*
* A passing, clean PR diff does not guarantee a functioning user experience.

---

### 1. Code Review vs. Experience Verification

| Aspect                     | **What PR Reviews Catch (The Code)**              | **What PR Reviews Miss (The Experience)** |
| -------------------------- | ------------------------------------------------- | ----------------------------------------- |
| **Focus**                  | Static correctness, architecture, maintainability | Dynamic runtime behavior, real-world UX   |
| **Key Strengths / Misses** | • Clean vs. messy implementation<br>              |

<br>• TypeScript errors & type integrity<br>

<br>• Business logic & unit edge cases<br>

<br>• Design patterns & code quality<br>

<br>• Unit test coverage<br>

<br>• Static security & performance flaws | • **Responsive design flaws:** Menus covering buttons on mobile screens<br>

<br>• **Session/Auth issues:** Stale tokens causing infinite redirect loops<br>

<br>• **Accessibility (a11y):** Keyboard focus traps inside modals<br>

<br>• **Feature flags:** Broken empty states or divergent branch flows<br>

<br>• **Async states:** Missing spinners, error banners, or out-of-order toast messages |

---

### 2. The 2-Step Review Workflow

1. **Step 1: Review the Code**

* *Question to ask:* **"Is the implementation correct?"**
* *Actions:* Inspect git diffs, verify static types, evaluate logic, review edge cases, and inspect unit tests.

1. **Step 2: Verify the Experience**

* *Question to ask:* **"Does the user's workflow actually work?"**
* *Actions:* Open preview environments/browsers, run the primary user journeys, and confirm visual and interactive results.

---

### 3. Turning "User Promises" into E2E Scenarios

| User Promise                                               | Corresponding E2E Scenario                                                                                         |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| *"After I submit the form, I’ll see a success message."*   | $\text{Fill Form} \rightarrow \text{Submit} \rightarrow \text{Wait} \rightarrow \text{Verify Success Toast}$       |
| *"A logged-out user can sign in and reach the dashboard."* | $\text{Login} \rightarrow \text{Authenticate} \rightarrow \text{Redirect} \rightarrow \text{Verify Dashboard DOM}$ |
| *"Users can close the modal with the keyboard."*           | $\text{Open Modal} \rightarrow \text{Press ESC Key} \rightarrow \text{Verify Modal Closed}$                        |

---

### 4. Recommended Tooling Stack

* **Collaboration & Pull Requests:** GitHub, Graphite *(for stacked PRs/faster cycles)*
* **Automated Code Insights:** CodeRabbit, Greptile *(AI-assisted context reviews)*
* **E2E & Experience Verification:** Bug0 *(FDE-authored scenarios)*, Passmark, Playwright *(browser execution engine)*

---

### 5. Summary Mental Model

$$\text{Code Review (Does code make sense?)} \;+\; \text{E2E Verification (Does the user journey work?)} \implies \mathbf{High\text{ }Confidence\text{ }Merge}$$
